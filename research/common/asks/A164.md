### Proposed setup
On a cloud workspace, for a deep audit only:

1. Install pinned `@colbymchenry/codegraph` at 1.6.2 (Muse confirms that version string still resolves before the test).
2. `codegraph init` inside the workspace. Do not commit `.codegraph/`. If the A/B says to keep doing this, a follow-up adds `.codegraph/` to `.gitignore` (today only `daemon.pid` is ignored).
3. Query caps: `codegraph context "<task>" --no-code -n 10`. At most two `callers` or `impact` follow-ups. Muse confirms those flags exist on 1.6.2; if a flag is absent, record the real flag and use the same cap (10 hits, no source bodies in the first call).
4. Route or commit questions go to `node scripts/route-map.mjs` and `scripts/commit-impact.sh` first.

### Token-budget rules
Index first. Then at most about 12 source files opened per audit. If the index is missing or the cap is hit, stop and report `blocked` with the question still open. No broad tree sweeps and no second agent hired to read the tree.

### What Muse measures
Five tasks, same questions on both arms (CodeGraph caps vs grep/read). Record tokens and whether the answer named the right file. Tasks should be lookups already answered in the repo (a route, a caller, a score function, a study id, a commit's touched files) so the right file is knowable. Report the five pairs in Reviews. A win is fewer tokens and no wrong file. A loss, or a tie, means cloud audits stay on route-map plus grep, and this row does not become a required install.

### Acceptance
Reviews has the five-task table (tokens and right/wrong file per arm) and a one-line keep or drop. No `.codegraph` path in the commit. Status stays `open` until that measured note exists.

### Cost
One cloud session, one index build, five paired questions. No database. No score run.
