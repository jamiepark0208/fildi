## Ask
Fix three High correctness defects in the fix4 horizon sweep (`scripts/watchlist_sync/analysis/conditional_engine.py`), plus four Mediums in the same commit. The sweep's confluence-filtered cells are mislabelled until re-run.

## Detail
- **H1 — Confluence filter runs on the wrong timeframe.** `run_horizon_sweep` (~L1589) + `run_conditional_strategy` (~L1062): each horizon loads one `higher_tf` into `ctx`, but `run_conditional_strategy` only reloads `ctx` when `bar_tf` differs — `higher_tf` is ignored when a ctx is supplied. `ema20_1h` / `rsi40_1h` run on 15m bars for scalp/day; `ema20_15m` runs on 1h bars for swing. 2 of 3 non-none filters mislabelled in every horizon. Fix: key the ctx reload on (`bar_tf`, `higher_tf`); re-run the sweep. Pass: a 1h-filtered scalp cell and a 15m-filtered swing cell each use the named TF's bars.
- **H2 — Higher-TF RSI read from the wrong dates.** `_align_higher_tf_entry_mask` (~L884): the full-series `rsi_higher` dict is passed as `rsi_cache` while `closes_hi` is a single session, so `hi_ok[j]` reads RSI from the first sessions of the sample. Affects `rsi40_1h`; EMA filters unaffected. Fix: align by timestamp. Pass: `hi_ok` for a mid-sample session matches RSI computed on that session's own dates.
- **H3 — Incomplete higher-TF bar lookahead.** The filter uses the last higher-TF bar with `ts_hi <=` entry time, but `ts_hi` is the bar's start; a 15m/1h bar that started before entry but ends after it is still forming, yet its close-derived RSI/EMA is used as if known at entry. Fix: require the bar's end `<=` entry time. Pass: no filter value depends on a bar that ends after the entry.
- **M1 — Deep-OTM global fallback pre-empts the ticker's own bucket.** `round_trip_frac` (~L171): `gl = _fallback_bucket("deep_otm", ...); if gl < 0.99*DEFAULT: return gl` runs before the ticker-bucket lookup, overriding ticker-specific calibration whenever a global deep-OTM bucket exists below 0.396. The added deep-OTM test uses empty `buckets`, so it never exercises this branch. Fix: check the ticker bucket first; add a test with both buckets present.
- **M2 — Failed months marked done.** `a359_bars_1m.py` `backfill_ticker` (~L145): `done.add(ck)` + state write happen unconditionally after `fetch_month`, even on non-200 / empty df — a failed month is never retried. Same failure class in 96fbd54 (~L136–142): a 200 with an empty `df` still marks the month done. Fix: mark done only on a non-empty successful fetch.
- **M3 — Stale-cache threshold is OPRA_START+3d, not freshness vs today.** `load_bars_for_timeframe` (~L740): once the parquet cache max date passes 2025-10-04, no refresh is ever attempted; a truncated backfill silently yields a truncated sweep window. Fix: refresh when cache max date is older than the latest available date.
- **M4 — `max_bars` not scaled by `bar_minutes`.** `_scalp_exits` / `_swing_exits` (~L1589): `tstop30m` = 30 bars is 30 min on 1m but 60 min on 2m; `tstop_5d` = 390 bars is ~16 days on 1h and 390 days on 1d — effectively no stop for swing cells. Fix: scale `max_bars` by `bar_minutes` (or express stops in minutes/days).
