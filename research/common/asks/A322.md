# A322 — Setup-but-unused credentials verdict: Codiv keep/drop, S&P Global auth+license
**From → to:** Muse → Cursor · **Date:** 2026-11-02 · **Status:** planned

## Ask
Decide the fate of the two credentials the Oct 24 inventory (A263) found set up but unused: the Codiv hosted key (zero callers) and S&P Global (never authenticated). Every live secret must end with a documented use and an owner, or be removed. No third outcome.

## 1st-level analysis (what happened)
- Codiv: `CODIV_API_KEY` set (49 chars). Code references: only A129/A263. Never probed (would spend the hosted token grant). Local OpenJev is the system of record; hosted Codiv is its unused twin.
- S&P Global: Claude.ai connector + local plugin (`sp-global`) need auth; no key in `.env.local`; no repo caller. Capital IQ-class fields would duplicate FactSet + LSEG if a license is ever turned on. Current status: not usable.
- Both sit in the "available, not used" class the settings catalog panel was built to expose (A264). This row turns that exposure into verdicts.

## 2nd-level analysis (why it matters)
- An unused live key is pure perimeter: secret material with no return. Keeping one needs a real overflow story; dropping one shrinks the blast radius.
- S&P Global is the mirror case: a potentially valuable third referee source (vendor disagreement is the A318 problem) that is currently worth exactly zero because auth + license were never checked. Checking both is cheap; assuming either is not.

## Use cases
- **UC1 — Codiv as OpenJev overflow.** If the local model is the constraint (Mac down, eval backlog), hosted Codiv answers the same asks. Why: eval continuity for the shortlist/headline/controls jobs. Expected value: a documented overflow procedure, or a removed key — both better than an unexamined secret.
- **UC2 — S&P Global as third referee.** Kensho tearsheets / earnings previews as an independent cross-check on FactSet/LSEG gold values. Why: A318's core problem is vendors disagreeing; a third independent source is the thing that would actually help referee disputes. Expected value: a referee candidate with measured agreement, or a clean drop.
- **UC3 — Perimeter hygiene as its own deliverable.** The verdicts themselves, recorded in the catalog, become the audit trail the next inventory reads instead of rediscovering two mystery keys. Why: stops this exact question from recurring. Expected value: the next A263-style audit finds zero unaccounted keys.

## Steps
0. Codiv minimal probe: one small eval subset through the hosted tier, costed (tokens spent vs the 100M grant), same asks as the local eval, answers compared. Verdict: keep (documented overflow procedure + owner) or drop (remove the key from `.env.local` + record the removal).
1. S&P Global auth attempt via the connector + plugin. If auth fails → drop, record. If auth passes → license check (does the license permit this use? written answer from the terms, not an assumption). If license fails → drop, record.
2. If S&P auth + license both pass: one cross-check pilot (5 names, tearsheet fields vs FactSet/LSEG gold, agreement report) → adopt (catalog row, metered) or drop.
3. Catalog rows for both verdicts either way — kept sources get full rows (feeds, limit, metering); dropped sources get recorded-drop rows, not silent deletion.
4. Reviewing agent (Claude, ≤20-line summary when pool recovers): propose 2+ additional use cases from these worked examples before the row closes. Grok may red-team the license reading.

## Downstream impact
- Secrets perimeter: a drop removes live key material. An adopt adds a metered source to the catalog panel.
- No score input under this row. Any S&P referee use in gold decisions is a separate row with its own validation (same boundary as A318/A319).

## Upstream data dependencies + maintenance
- Keys live Mac-side in `.env.local` only, never in the repo. Grant balance (Codiv) and license terms (S&P) are the upstream facts; both get recorded in the row, not assumed.
- Kept keys get an owner + a re-check date; the next inventory verifies them instead of rediscovering them.

## Pass / fail bars
- **P1.** Both verdicts recorded with evidence (probe numbers for Codiv; auth result + license answer for S&P).
- **P2.** No key left unaccounted: every kept key has a documented use + owner; every dropped key is removed + recorded.
- **P3.** Catalog rows updated for both outcomes.
- **Stop rule.** License ambiguity = drop, not "proceed and see." A probe that spends meaningful grant without a verdict = fail.
