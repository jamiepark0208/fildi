## 1st-level analysis: why this matters to fildi

Fildi sells American-style equity puts. A European Black-Scholes price understates an American put by the early-exercise premium — on the sheet's own example, 5.5735 vs ~6.09, a ~0.52 (~9%) gap. Any fair-value, put-edge, or backtest-pricing path that leans on European BS carries that bias on every American name. The three American methods on the sheet converge (~6.089 binomial/FD; LSM 6.04, low as its own bias note predicts), so the sheet is internally consistent textbook material, not a novel claim — no tool to test, nothing institution-gated. Value here is a reference pricer, not a strategy.

## 2nd-level analysis: what is actually new vs fildi

Fildi already computes fair values (Oct 22: yield percent→decimal normalization fixed a fair-value collapse; automation work references FV jump filters), and prices live chains from Schwab. What fildi does not have, as far as this row can establish, is an independent model pricer to validate chain mids and fair values against — a second opinion that flags a stale or broken quote instead of trusting the chain. That is the build: a small validation pricer, not a pricing replacement. Live quotes stay primary; the model is the check.

## Use cases (why, expected value)

Why: a stale/broken chain mid currently flows straight into edge and fair value. Expected value: bad-quote flags before they become bad edges.
2. **American-vs-European bias audit on put edge.** Recompute put-edge inputs with the American pricer and measure how much edge the European approximation was giving away or overstating. Why: the ~9% example gap is large relative to put-selling margins. Expected value: a quantified bias number, and a corrected edge where it matters.
3. **Backtest pricing leg for A246.** The A246 closed loop needs a pricer for generated candidates; a validated American pricer is its pricing dependency. Why: backtests priced on European BS misstate American-put payoffs. Expected value: A246's backtests stop carrying the early-exercise bias.

## Jamie revision 2026-10-24 — the case FOR theoretical models (replaces validation-only framing)

Jamie's correction, adopted: the last version reported the gap ("we don't have binomial/FD/LSM") and stopped. The right question is "we don't have X — should we, and can X make recommendations better?" Answer: yes, and here is how. Validation (the original use case 1) stays, but it is now the smallest use, not the point. Models complement the empirical edge factors; they do not replace them — theory is the anchor that keeps empirical factors from overfitting, and market prices stay the primary quote.

### How each model earns its place in recommendations

- **Black-Scholes (already in fildi, Greeks only — expand its job).** Invert it to get a consistent IV surface from chain prices; use delta as the strike-selection target (fildi's 0.10–0.25Δ lane already thinks this way — make it model-driven, not ad-hoc); use theta curves to choose DTE; use delta as a probability-of-profit proxy for ranking. Fast, O(1), runs on every chain row.
- **Binomial (NEW — the highest-value addition for a put seller).** Prices the American early-exercise premium European BS ignores (~0.52, ~9%, on the sheet's own example) — so short-put edge stops being overstated. Gives the exercise boundary and assignment-risk flag per position, handles discrete dividends at ex-dates, and prices scenarios through the lattice (what is this put worth if spot drops 5% in 3 days?).
- **Finite Difference (NEW — the book-level tool).** One solve prices a whole grid: every strike's price and Greeks at once, so the entire chain can be scanned for mispricing in one pass. Powers book-level scenario P&L (book value if SPY gaps -5% tomorrow, assignment clusters by strike) and barrier/local-vol structures BS cannot touch.
- **Monte Carlo LSM (NEW — the risk tool).** Joint simulation of the paper book gives VaR/CVaR, multi-leg payoff distributions, and path-dependent features. Not for pricing vanilla puts — for answering "how bad can this book get, together?" which no single-name model answers.
- **Ensemble disagreement as an uncertainty signal (NEW).** When BS/binomial/FD/LSM disagree beyond tolerance on the same contract, that is information: illiquidity, jump risk, dividend surprise, or a bad IV. Downweight or skip the recommendation instead of trusting one number.
- **Model-vs-market gap as an edge signal (NEW).** Model value vs chain mid: selling premium above model value = selling rich; below = selling cheap. A persistent, validated gap is a recommendation input, not just a data-quality flag.
- **Historical price synthesis (NEW — unblocks A246).** LSEG optlab holds ~1.3 strikes/name/date, so most backtests cannot run on observed history. Synthesize historical option prices from spot + vol history with binomial/FD, and backtests that today cannot run become runnable. This is the pricing leg the A246 loop needs.
- **Illiquid-strike pricing (NEW).** Where chain quotes are absent or spreads are absurd, the model prices the strike — recommendations stop being limited to the liquid names with tight quotes.

Ensemble-disagreement downweighting + illiquid-strike pricing.

### Corrections: what already exists (code-checked 2026-10-24)

- **Black-Scholes already feeds recommendations, two ways.** (1) `option-scorer.ts` (Layer 2 pure scorer) takes put delta from `bsGreeks` — `DELTA_SWEET_HIGH` / `DELTA_MAX` bands and delta-weighted buffer are scorer inputs, so BS delta already ranks strikes. (2) `backtest_puts.py` already prices puts with Black-Scholes at LSEG 30d ATM put IV, with a realistic-fill haircut, graded at expiry on real closes. BS is not new to fildi; it is new only as a *pricer of record* beyond Greeks + backtests.
- **Monte Carlo already exists — for book assignment risk, not pricing.** `pm_alerts.py` runs 20k paths to the nearest expiry (which puts assign, longs move on 60-day realized vol, empirical Cholesky correlation from A117, one-factor RHO = 0.6 fallback), calibrated on 926 real puts (predicted 18% ITM vs 21% realized — no detectable bias). LSM pricing is new; Monte Carlo as a technique is not.
- **VaR/CVaR already exists — parametric, not simulated.** `portfolio-risk.ts` computes 1-day 95% parametric VaR/CVaR from local `prices_historical` (no Yahoo fan-out). LSM's job is to *upgrade* this (non-normal, joint option payoffs, path dependence), not to introduce book risk.
- **Still genuinely missing (zero files 2026-10-24):** binomial, finite-difference, and LSM *pricing*; whole-grid Greeks; model-vs-market mispricing as a scorer input; synthesized historical option prices. Those are the build.

### Verified build map (enhance vs build)

ENHANCE (exists, extend — do not rebuild):
- `options-greeks.ts` (+ test): BS delta/gamma/theta, pure, no IO. Binomial/FD/LSM go beside it in the same pure-math style, same test discipline (sheet reference numbers as locked tests).
- `option-scorer.ts`: add model outputs as scorer inputs (American premium, model-vs-market gap, ensemble disagreement) with the existing null-drops-and-renormalizes invariance — a missing model value must never zero a score.
- `backtest_puts.py`: add binomial/FD as alternative pricers alongside BS; same grading on real closes, so model-vs-model comparisons are apples-to-apples.
- `pm_alerts.py` (20k-path MC) + `portfolio-risk.ts` (parametric VaR/CVaR): LSM upgrades these two, reusing their calibration (926-put check, Cholesky/fallback) rather than inventing new risk plumbing.
- `options-iv-term.ts`, ATM IV snapshots (0024), `option-chain-history.ts`, LSEG `daily_history`: the models read these; no new IV fetch, no new chain fetch. Dividend handling reads fildi's ex-date data (backfill-dividends script exists); if ex-dates are missing for a name, the binomial pricer flags it instead of silently pricing ex-div wrong.

BUILD (new): binomial pricer (first — highest value for American puts) → FD grid pricer → LSM pricer; model-vs-market gap + ensemble-disagreement scorer inputs; historical price synthesis job (only where observed prices are missing, calibrated where they exist).

### Optimization: compute tiers + OpenJev + fildi cost architecture (mandatory)

- **Compute tiers — never run the expensive model on everything.** BS is O(1): runs on every chain row. Binomial runs only on the American shortlist (names passing the scorer's liquidity gates `MIN_OI`/`MAX_SPREAD_PCT`/`MIN_VOL`, plus short-put candidates). FD runs once per name per day; the whole grid is reused across all strikes of that name. LSM / 20k-path MC runs weekly at book level only, like `pm_alerts.py`'s existing cadence. A model that needs per-row LSM is a design failure — send it back.
- **OpenJev (A150 framework) as the cheap screen before model compute.** Local MLX, $0, zero inference tokens: P21 overnight-put-risk (AUC 0.60, calibrated) pre-screens which put names even deserve binomial/FD compute on a given morning; P11 (tier A) gates any failure-log review the pricing work generates. Same constraints as A246: Mac-local (8091/8092), VM cannot reach it, degrades gracefully when the Mac sleeps; `--summary` aggregates only; never final authority; never price predictions.
- **Snapshot discipline.** Model outputs are computed once (nightly, daily.py stage) and snapshotted like option scores (`snapshot-option-scores.ts` pattern); the UI and scorer read snapshots. No per-request repricing, no per-user recompute.
- **Metering.** All LLM use in this work (hypothesis/proposal only — the models themselves are pure math, zero LLM) is metered through `ai-pricing.ts` (A130); the synthesis job's cost is logged the same way.
