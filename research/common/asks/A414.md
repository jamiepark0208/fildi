# A414: Capital plan: long-put odds label reads backwards ("above breakeven" is the losing side)

## Ask
Fix a one-word direction error in the capital-plan sell reasons: a long put's odds are shown as "% odds to finish above breakeven", but the number is the chance of finishing below breakeven. For a put, above breakeven is the losing side.

## Detail
- Evidence (repo-watch 2026-11-19, commit `192b306`, CI green):
  - `artifacts/api-server/src/lib/capital-plan.ts`, `optionSource()`: `why` = `` `${Math.round(o.pBe * 100)} % odds to finish above breakeven` `` — direction-agnostic text.
  - `artifacts/api-server/src/routes/strategies.ts`, `capitalPlans()`: `pAbv = 1 - normCDF((ln(be/spot) + 0.5*sd^2)/sd)` = P(S_T > be); `pBe = type === "call" ? pAbv : 1 - pAbv`. For a long put, `be = strike - cost`, so `pBe` = P(S_T < be) = the win probability — the chance of finishing *below* breakeven. For calls the label is right; for puts it is inverted.
  - Same inversion in the tier-2 header comment in `capital-plan.ts` ("long option with < 15 % odds to finish above breakeven").
- The tier logic itself is correct: `pBe < 0.15` = low win odds for both directions, so no ranking change — only the displayed wording is wrong.
- Fix: make the label direction-aware — calls: "X % odds to finish above breakeven"; puts: "X % odds to finish below breakeven" (or "in profit"). Fix the header comment the same way.
- Pass/fail: a long-put source with pBe 0.10 shows "10 % odds to finish below breakeven" (or equivalent); a long call still shows "above breakeven"; `capital-plan.test.ts` gains one assertion on a long-put source's `why` text; CI green.
