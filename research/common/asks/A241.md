**P4 — Standalone VM tests (Cursor; ~0.5 day).**
- Pass: 3 consecutive trading days with 0 failed public jobs; peak RSS < 850 MB, swap < 500 MB, 0 OOM kills (`journalctl -k`); 1-week VM egress projection < 300 MB; GCP billing shows $0.00; reboot test — services come back unattended.

**P5 — Side-by-side parity (Cursor builds the diff; Claude sets/accepts the bar; ≥ 10 trading days incl. 2 Fridays, 2 Saturdays, 2 Sundays).**
- `scripts/parity/vm_vs_mac.mjs` (new, branch): on the Mac, opens an SSH tunnel (`ssh -L 15432:127.0.0.1:5432`), runs the same aggregate SQL on both DBs per PUBLIC table: row count, max(updated/created/as-of ts), and per-day `md5(string_agg(key cols order by key))` over the last 10 days. Only aggregates cross the tunnel (KBs). Also compares job-run status (VM `enrichment_runs` / scheduler stamps vs Mac).
- Pass bar (proposed; Claude owns final numbers):
  1. Job health: 100 % of scheduled VM public-job slots ran; ≤ 1 auto-retry per job per week; 0 silent skips.
  2. Freshness: per table, VM max(ts) ≥ Mac max(ts) − one job interval.
  3. Deterministic derived tables (scores, option_score_snapshots, model_recs, regime_grades) from identical inputs: checksum match on ≥ 95 % of ticker-days; every mismatch explained by an input-source difference (Schwab/LSEG on Mac vs Yahoo on VM).
  4. Source-dependent tables (prices_historical, fundamentals): ≥ 99 % ticker-days present on both; close/field values within 0.5 %.
  5. LLM outputs (event bullets, explain_cache if copied): coverage parity only (same tickers/days have output), not text equality.
  6. Resources/cost: P4 limits held for the whole window; $0 billed.
- Output: daily parity report file + one summary line in this row's Status notes. Fail on any of 1–2 or 6 → fix and restart the 10-day clock.

**P6 — Cutover (only after the P5 pass AND Jamie says "go"; Cursor; ~0.5 day).**
- Mac: set `FILDI_HOST_ROLE=private` (skips exactly the jobs now on the VM); add `scripts/vm-pull.mjs` (launchd on wake + every 30 min while awake, and before the 07:00 PT Model List): SSH tunnel → incremental upsert per PUBLIC table by id/updated_at watermark into the **existing local DB**, so the UI, daily.py and every Mac reader keep reading local Postgres unchanged. Never a routine full dump (egress).
- Mac-originated public inputs the VM can't fetch (LSEG street-PT, Schwab 1m bars) stay Mac-written and Mac-only; nothing is pushed up unless Claude + Jamie OK it (license).
- Claude gate: Model List inputs (scores/prices) now arrive via pull; one full Model List day must match the last shadow day's expectations.
- Pass: 5 trading days post-cutover, Model List builds on time every day, pull lag < 30 min when the Mac is awake, Mac-off overnight → VM jobs still ran.

**P7 — Rollback (documented and tested once before P6).**
- Unset `FILDI_HOST_ROLE` on the Mac (+ unload the vm-pull launchd job) → Mac runs all jobs again on its own local DB, which was never altered except by pulled public rows (same tables the Mac jobs overwrite anyway).
- VM is disposable: delete instance + disk; nothing private ever lived there. Re-provision = rerun the Cloud Shell script + P2.
- Pass: rollback drill on one weekend day → Mac jobs green within one maintain cycle.

### Risks
- **1 GB RAM:** Node + Postgres + a Python/TS job can OOM. Mitigation: serial jobs, MemoryMax, swap, prebuilt JS, headless scheduler. Escape: Oracle A1 (12 GB) if capacity appears.
- **Shared vendor quotas:** shadow can starve the Mac (FMP/Finnhub/Polygon/AV/FactSet/Anthropic). Mitigation in P3; this is the main way shadow could "change the Mac" by accident.
- **Price-source drift:** VM has no Schwab/LSEG → Yahoo-only prices; Yahoo may rate-limit GCP IPs. Parity rule 3/4 measures it; if drift breaks scores, those jobs stay on Mac.
- **Hidden private coupling:** transcripts (reads today's plan), Model List intraday, trade expiry, desk ingest. Allowlist + role flag contain it.
- **Egress:** 1 GB/mo; parity + pull are incremental; a full dump down = ~month's quota. Alert at $1.
- **Credential on VM:** deploy key scoped to the VM only; no brokerage creds there; one Schwab refresher stays on the Mac (A72 Claude note).
- **Free-tier terms change:** VM is scripted and disposable; Supabase/Oracle fallbacks stay documented.
