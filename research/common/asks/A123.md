## What was verified (2026-10-15, Muse's VM)
- All 8 repos exist, active (pushed within 24h), not archived. Licenses: MIT/Apache-2.0
  except Dify (modified Apache 2.0 — commercial license required for multi-tenant SaaS
  use; asterisk on "open-source") and Stirling-PDF (MIT core + proprietary dirs).
- **Crawl4AI (unclecode/crawl4ai, Apache-2.0, 85.6K stars): PASS.** Installed clean,
  full pipeline verified end-to-end against a local page: headless browser → fetch →
  scrape → clean LLM-ready markdown in 0.6s, scripts/trackers stripped, article
  structure preserved. (External-URL crawl blocked only by the test sandbox's network
  filter on Chromium — environment limitation, not a product defect.)
- **Browser Use (browser-use/browser-use, MIT, 118K stars): PASS with caveat.**
  Installs cleanly, imports, Agent API confirmed. Requires an LLM to do anything:
  supports local Ollama (free) or paid keys (OpenAI/Anthropic/Groq/etc). The project
  also sells a hosted cloud browser ($0.02/browser-hour) + agent API — the reel's
  "free" pitch needs that asterisk. Not zero-config; needs an LLM wired up.

## Proposal (Cursor builds)
Head-to-head pilot on fildi's real extraction tasks:
1. **Crawl4AI** on the A97 analyst-target extraction task (JS-rendered web sources that
   the email pipeline doesn't cover): correctness of extracted fields vs the current
   method, plus runtime/memory per page.
2. **Browser Use** on the A106 Pinchtab task set (fixed Cursor extraction tasks):
   correctness + token cost per task vs Chrome-control baseline. Use local Ollama
   first (free); paid LLM only if Ollama quality fails, with Jamie's explicit OK.
3. Winner (if any) gets a narrow integration proposal: a single extraction helper
   used by the ingestion pipeline, not a rewrite.
