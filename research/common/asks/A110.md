# A110 — option_history.py loader re-run hazards (bars schema + chain cache key)

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-15
**Severity:** medium (finding 1 breaks the loader re-run; finding 2 is low)

## Context
Repo-watch review of 8118973b ("S017–S021: analysis framework … loader slimmed (~20 MB)"). The
loader's docstring claims "each step skips what is already stored → safe to stop and restart any
time". Two changes break that promise.

## Finding 1 (medium): optlab.bars schema change has no migration
8118973b shrank `optlab.bars` from 8 columns `(occ, date, o, h, l, c, v, vw)` to 5
`(occ, date, h, c, v)` — but the DDL is `CREATE TABLE IF NOT EXISTS`. On any DB where the loader
already ran, the table keeps the old 8-column layout, and the new positional
`INSERT INTO optlab.bars VALUES (%s,%s,%s,%s,%s)` (fetch_bars, ~line 158) fails with a
column-count error. First re-run after this commit dies.

Fix (pick one):
- Name the columns in the INSERT (`INSERT INTO optlab.bars (occ, date, h, c, v) VALUES ...`), which works on both old and new layouts; or
- add a one-time `ALTER TABLE optlab.bars DROP COLUMN IF EXISTS o/l/vw` guarded migration.

## Finding 2 (low): chains_fetched cache is not keyed on ref
`chain(conn, t, exp, ref)` (option_history.py ~line 143) stores only strikes within ±30 % of `ref`,
but the "already fetched" check is `(underlying, expiry)` only. A later study calling with a
different `ref` silently reuses the first ref's strike window — strikes it needs are missing,
no error. Fix: include the ref (or the window bounds) in the `chains_fetched` key, or re-fetch
when the requested ref differs from the stored one.

## Acceptance
- Fresh DB and pre-existing DB both complete a full loader run with no errors.
- `chain()` called with two different refs for the same expiry stores/returns the union the
  studies need (document the behavior in the module docstring).
