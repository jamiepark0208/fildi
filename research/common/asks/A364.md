## Findings (High)

- **B1 — Same-OCC events collapse, last wins.** `scripts/watchlist_sync/analysis/a357_lse_option_backfill.py`: `collect_s059_puts` / `collect_model_puts` / `collect_contracts` key dicts by OCC only (OCC encodes ticker+expiry+strike, not entry date). Two S059 events for one contract on different dates overwrite each other; `collect_contracts` lets a `model_recs` row silently replace an S059 contract, wiping `model_strike` and flipping `source`, dropping it from the regrade. Wrong fetch windows, lost S059 events. Fix: key by (OCC, entry date) or equivalent; re-run the backfill.
- **B2 — `smoke_validate` prints divergence but never fails on it.** Returns False only if <3 overlaps are found; a 50% price mismatch passes. Strike tolerance 8% accepts a different strike as the "same" contract; only the first overlapping date, max 3 contracts. The 32% INTC divergence is already noted in A357.md review text — and the run proceeded anyway because nothing can fail on it. Fix: fail on divergence above threshold, tighten the strike tolerance, cover all overlaps.
- **R1 — Verdict logic inverted.** `scripts/watchlist_sync/analysis/a357_regrade.py`: `verdict = "holds" if cov >= 0.60 and lines[-1] != "" else "underpowered"`. After the haircut loop `lines[-1]` is `""` whenever any haircut produced output, so "holds" is impossible when edges are actually computed; conversely "holds" fires on coverage alone when no haircut has enough weeks and there are no ratios. The verdict never looks at edge sign/size despite the pre-registered hold/weaken/fail framing. The step-4 verdict is wrong in both directions. Fix: verdict from edge sign/size + coverage; re-issue the step-4 verdict.

## Findings (Medium — fix in the same pass)

- **B3** Resume treats "any row" as "complete" — a truncated/partial fetch is never refetched; missing dates stay missing forever, and the regrade's `MIN_BACKFILL_OCC` gate counts partial OCCs as backfilled.
- **B4** `fetch_one` returning `ok_0` (zero rows) counts as success toward `--min-ok` (≥15 smoke gate).
- **B5** `--smoke-validate` without `--limit` silently validates nothing and exits 0.
- **R2** Coverage denominator excludes silently dropped events — reported `cov` is overstated against the true S059 population, so the 60% gate is easier to pass.
- **R3** `_entry_close` silently substitutes adjacent-day closes, including `entry+1` (look-ahead) as the "traded entry premium", with no record of which date was used.
- **R4** `_events_by_week` matches contracts by ticker+entry+expiry only, takes `cands[0]` — never checks the candidate's snapped strike equals this event's model strike; two events sharing ticker/entry/expiry can be cross-paired.
- **B6** `_spot_at` / `strike_for_event` drop events on missing entry-date spot with no log/count.
- **B7** `no_listed_strike` log OCC is built from the unsnapped model strike — phantom key, unauditable.
- **B8** `collect_s059_sample` calls full-table-scan `load_skip_sets` per event; `--limit` runs sort newest-first, starving the oldest pending.
- **B9** `collect_model_puts` bypasses the snap entirely. **B10** Exact-expiry only, no nearest-expiry fallback.
- **R5** IV-unit inconsistency across three lines (`_model_prem_snap` scale-agnostic, backfill decimal, `_attach_traded` unconditional /100 — `put_delta` likely on the wrong side, though delta is never read downstream). **R6** Report overwritten per run with no timestamp/run-id/rev; `A352.rebuild_book` write side effects unverified. **R7** `MIN_BACKFILL_OCC=500` counts DISTINCT OCCs with ≥1 row; weeks with <20 names dropped silently.
