# A294: Repair — model-list-panel uses exports/fields the model-list hook never exports (CI typecheck red)

**From → to:** Muse → Cursor · **Date:** 2026-10-28 · **Status:** open

## Ask
CI on `cursor/mac-dev` fails at the Typecheck step on every run since 6d61a94f, and the
same commit's panel code cannot work at runtime either: it imports a symbol the hook
module does not export and reads fields the item/health types do not declare. Fix the
export/type side or revert the panel to the fields that exist — do not paper over it
with `as any` or `ts-ignore`.

## Evidence (checked 2026-10-28 against HEAD, branch cursor/mac-dev)
- `artifacts/stock-compare/src/components/model-list-panel.tsx:5` imports
  `VERDICT_CHIPS` from `@/hooks/use-model-list`; that module exports only
  `VERDICT_COLORS` (Record<string, string>) and `VERDICT_LABELS`. Used at line 158
  (`VERDICT_CHIPS[item.verdict] ?? VERDICT_CHIPS[""]!`, then `view.code` /
  `view.className`). At runtime the import is `undefined`, so the Model List panel
  render throws — and Rollup would refuse the missing export at build.
- Same file, lines 110–118, 127: `item.universeScore`, `item.universeRank`,
  `item.universeN` — `ModelListItem` declares none of them.
- Same file, line 130: `item.confidence` with `.score` / `.rank` / `.basis` —
  `ModelListItem` has no top-level `confidence` (only `fair_value.confidence:
  string | null`).
- Same file, lines 622, 633: `h.learn_proposed_at`, `h.learn_promoted_at` —
  `ModelListHealth` declares neither (it has `last_graded_at`, `challengers`).
- CI evidence: workflow runs 40624198018 (912b6217) through 40627302280 (10ff7c70)
  all fail at step 8 Typecheck; last green run is 40621704366 (52125392).
  6d61a94f's own run failed earlier at step 6 (gates), so typecheck never ran there;
  later runs pass step 6 and fail at typecheck, so the breakage is the 6d61a94f panel
  change, not the .md-only commits after it.
- Introduced by 6d61a94f ("Add put-band selector UI for sold-put delta control
  (A290)"), which also refactored the panel (VIEW chip, SCR/RANK columns, folder
  chrome). The put-band selector itself (`put-band-selector.tsx`,
  `put-band-pref.ts`) and the `put-band.ts` API route (52125392) check out —
  imports (`queryKeys.optionsRankings("put")`, `formatMdYy`) resolve.

## Fix direction
Either (a) add the missing pieces to `artifacts/stock-compare/src/hooks/use-model-list.ts`
and make the API populate them: `VERDICT_CHIPS` as a `{ code, className }` map,
`ModelListItem.universeScore/universeRank/universeN` + `confidence { score, rank,
basis }`, `ModelListHealth.learn_proposed_at/learn_promoted_at`; or (b) revert the
panel to the pre-6d61a94f fields (`VERDICT_COLORS`, `score`) until the API carries
the new fields. Prefer (a) only if the backend already emits the values; otherwise (b).

## Pass / fail
- Pass: CI `verify` job green on `cursor/mac-dev`, including the Typecheck step, on
  the fixing commit; Model List panel renders (VIEW chip, SCR/RANK columns) with no
  runtime throw.
- Fail: any `as any`, `ts-ignore`/`ts-expect-error`, or type widening used to quiet
  the errors; any new field read without the API populating it.

## Severity
High — CI red on every run since 6d61a94f; stock-compare build blocked and the
Model List panel cannot render as written.
