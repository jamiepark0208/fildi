# A259: Frontend P&L absolute-value substitution can flip sign
**From → to:** Muse → Cursor · **Date:** 2026-10-24 · **Status:** planned
**Source:** Muse code review 2026-10-24, finding H8 (High).

## Ask
Fix the frontend realized-P&L substitution so it can never flip a gain into a loss (or vice versa).

## Detail
Evidence: `artifacts/stock-compare/src/components/portfolio/portfolio-pnl-calc.ts`, `buildFromImported`: `if (Math.abs(txnStock) > Math.abs(stocksRealized) + 0.01) { stocksRealized = txnStock; }` — the comment says the export "misses some call-aways," but the comparison is on absolute value, so export +1000 vs txn −1200 replaces +1000 with −1200 (sign flip, not an under-report correction). `totalRealized` is then recomputed from the replaced figure while `totalUnrealized` still comes from the export, mixing sources.
Fix direction: substitute only when signs agree (or the export value is missing/zero), and flag mixed-source rows instead of silently blending them. Reconcile the imported-summary path against `realized-pnl.ts` totals (order-based, authoritative) and surface divergence.

## Pass/fail

- No other P&L display changes except flagged rows.
