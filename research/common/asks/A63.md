## Ask
`fetchAndStoreOHLCV` merges bars with Schwab > Yahoo priority, but the DB write uses `.onConflictDoNothing()` — a Yahoo bar stored last week permanently blocks a better Schwab bar for the same date. The ranking only holds for dates not yet in the DB.

## Detail
`artifacts/api-server/src/lib/indicators.ts:499` — the insert into `prices_historical` uses `.onConflictDoNothing()`. Any date already stored (even from a lower-ranked source) is never overwritten, silently defeating the source ranking built in a68c3d11.
Fix: upsert honoring source rank — overwrite the stored bar when the incoming source outranks it, keep otherwise. Add a regression test: store a Yahoo bar for date D, then fetch with Schwab available for D → stored bar becomes Schwab-sourced. Severity: degraded (technicals scored on worse data). No quota impact — same fetch count. [quant]: price data feeds technical scores.

## Reviews
**Claude plan 2026-10-14:** (late — missed at 10-11 session start). Sound bug; add these before build:
1. **Adjustment convention.** Schwab pricehistory and Yahoo/FMP/Polygon differ on split/dividend adjustment (A16: splits are never back-adjusted here). Overwriting single dates with a different-convention source creates fake jumps that poison RV20, RSI, z-distance and every backtest. Rule: only replace a bar if |new/old − 1| < 2% OR the whole ticker series is re-pulled from the higher source in one pass; else log a `source_conflict` row and keep old.
2. **Partial bars.** Never let an intraday (today, market open) bar outrank a final bar; final > partial regardless of source.
3. Needs a `source` column on `prices_historical` (check it exists; backfill `unknown` = lowest rank).
4. **Eval (acceptance):** dry-run count of bars that would change by source pair + distribution of |Δclose|; maintain's `jumps` metric must stay 0 after the run; re-run S015 (`analysis/trade_mistakes.py`) and S003 trades — headline numbers must move < 0.05 pt, else investigate before merge.
