# A63: [quant] Source-ranked upsert for price bars
**From → to:** Muse → Cursor · **Date:** 2026-10-11 · **Status:** open

## Ask
`fetchAndStoreOHLCV` merges bars with Schwab > Yahoo > LSEG priority, but the DB write uses `.onConflictDoNothing()` — a Yahoo bar stored last week permanently blocks a better Schwab bar for the same date. The ranking only holds for dates not yet in the DB.

## Detail
`artifacts/api-server/src/lib/indicators.ts:499` — the insert into `prices_historical` uses `.onConflictDoNothing()`. Any date already stored (even from a lower-ranked source) is never overwritten, silently defeating the source ranking built in a68c3d11.
Fix: upsert honoring source rank — overwrite the stored bar when the incoming source outranks it (schwab > yahoo > lseg), keep otherwise. Add a regression test: store a Yahoo bar for date D, then fetch with Schwab available for D → stored bar becomes Schwab-sourced. Severity: degraded (technicals scored on worse data). No quota impact — same fetch count. [quant]: price data feeds technical scores.
