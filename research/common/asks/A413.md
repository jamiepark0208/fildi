## Problem (1st-level)

The evening recap's "Fildi says" section has no data source the VM can reach. The VM cannot touch Mac Postgres (`127.0.0.1`) or the Mac api-server (`127.0.0.1:8091`); `device.invoke` reads files only. Every fildi analytical output is evening-only in principle and unreachable in practice:

- `put_recs` — `scripts/watchlist_sync/put_recs.py` → `watchlist_sync.put_recs_daily` (strike, expiry, DTE, `odds_otm`, tier, score, gates, earnings flag). "The table every surface reads."
- `option_score_snapshots` — `snapshot-option-scores.ts` → `option_score_snapshots` (spot, premium, `weekly_income_pct`, `otm_pct`, delta, `strike_iv`, dte, `option_score`, `component_scores`, `atm_put_iv`, `iv_vs_realized`).
- Risk-reversal — `risk-reversal.ts` + `scripts/watchlist_sync/rr_skew.py` → `watchlist_sync.rr_skew_daily` (rr25, atm_iv, p25, c25; ranked vs own 60d + GICS peers).
- IV rank — `scripts/watchlist_sync/iv_rank.py` → `watchlist_sync.iv_rank_daily` (pctile 0–1; LSEG 30d ATM put IV first, tastytrade second but off by default).
- Options flow — `scripts/watchlist_sync/options_flow.py` → `watchlist_sync.options_flow_prints` + `options_flow_daily` (call/put premium, blocks ≥$250k, bursts, `premium_x_norm` vs own 20d median, top-5 contracts).
- GEX — `gex-daily.ts` + `snapshot-gex-daily.ts` → `watchlist_sync.gex_daily` (SPY/QQQ, net/call/put GEX, gamma flip, call/put walls).
- Macro — `scripts/watchlist_sync/vix_daily.py` → `watchlist_sync.macro_daily` (VIX, VIX3M, HY OAS `BAMLH0A0HYM2`).
- Pundit views — `figure_views` (figure_id, claim, asset, direction, horizon, confidence, source_url, resolved, forecast_p); registry hardcoded in `figure-views.ts` (`FIGURE_REGISTRY`, 15 figures).

Verified Nov 18 from repo HEAD `e6f1d49` (read-only gh-api inventory). The recap cron (Nov 18) already reads the snapshot first when it exists — the consumer is wired; the producer is missing.

## What this builds (2nd-level — revised per Grok reviews 2026-11-18/19; these rules win over the original draft)

A small step in the Mac's `daily.py` — the LAST step in the publish chain, after "options flow" — that writes ONE JSON file to `My Drive/fildi-brief-snapshot/` (sibling of the desk-commentary `DEFAULT_DRIVE_DIR`; the TradeDash Briefs folder parses every `.json` into `desk_commentaries`, so the snapshot must NOT go there):

- `fildi-brief-snapshot-YYYY-MM-DD.json` + `fildi-brief-snapshot-latest.json` (same content, latest pointer). Schema 1, top-level `as_of` = ET now.
- Puts: top 15 rows with `pass` true from `put_recs_daily`, ORDER BY rank, only when `computed_at` is this ET day. Fields: ticker, strike, expiry, dte, odds_otm, tier, income_wk_pct, gates. App order is rank. `put_recs_daily` is `(as_of, ticker, rank, pass, payload)` — there is NO score column. Leave out option_score and fair value, and the full payload.
- IV rank: for those 15 plus DISTINCT symbol on the latest `portfolio_positions` snapshot (symbol only, no qty, no account id). Keep rows whose `date` = current_date, the writer's stamp. `pctile` 0–1. The resolver is soft and leaves yesterday on failure — a latest-row read would republish stale numbers, so the date gate is the guard.
- Skew: for the same names when `computed_at` is this ET day, plus ownPct and sectorPct from the copied SQL (the skewRanks SELECT in `strategies.ts` — copy it, do not invent a second rank). Null below 10 own days or 5 peers. Leave the HTTP route and `rr_answer` alone (saved answer can be 24h old).
- Flow: top 5 by `premium_x_norm` on max(day) when that day is the last session or the one before; label the day. Blocks count prints ≥ $250k; the tape is prints ≥ $25k; side is call/put. Flow is one session late on purpose.
- GEX: SPY/QQQ with `as_of` = lastCompletedSessionYmd.
- Macro: latest vix, vix3m, and hy_oas (percent) each with its date; drop all three when inflight `out/runs/inflight-<ET day>.json` lists step "vix".
- Figures: `public.figure_views` for this ET day, cap 15, otherwise omit the key.
- Each section carries its own `as_of`. A failed writer omits its section, never a stale value.
- No secrets in the file: no DATABASE_URL, no credentials, no account identifiers. Verified by grep before the first ship.
- File size target <200KB. No UI changes. No live-money changes (read-only snapshot of existing tables).

## Use cases (why + expected value)

1. **"Fildi says" becomes real.** The evening recap cites top put_recs by odds, IV rank for book names, and risk-reversal skew direction from fildi's own analytics instead of generic premium commentary. Expected value: the recap stops being a news summary and becomes the desk note Jamie asked for Nov 18 — the section that differentiates it from StreetAccount.
2. **The brief becomes a verification layer for fildi.** With fildi's own bars and scores in hand, the recap run can check a brief number against fildi's data before shipping (the Nov 18 WTI 1W/1M error was a lookup mix-up; the same class of error against fildi's bars would surface as a code/data bug and become an ASKS row). Expected value: one class of brief error caught at the source, plus a real bug-detection path for the repo.
3. **Options-flow and GEX lines stop being display-only guesses.** The recap quotes the flow tape's top unusual names and the SPY/QQQ gamma flip from fildi's own tables instead of recomputing them from public chains. Expected value: the recap's levels line uses the same numbers the app shows, so Jamie never sees the brief and the app disagree.

## Downstream impact

- Evening recap cron step 0 reads the snapshot first (already wired Nov 18); the Friday brief-review cron can score "Fildi says" coverage against the snapshot's presence.
- No change to the morning brief (public-data-only by design — the Mac is asleep at 06:10).
- No change to any UI tab, any writer, or any live-money path. The exporter is a read-only consumer of tables that already exist.
- If the exporter is late or missing, the recap falls back to the existing DB/API reads, then to generic commentary — the brief never blocks on it.

## Upstream data dependencies + maintenance

- Depends on the nightly `watchlist_sync` writers (put_recs.py, iv_rank.py, rr_skew.py, options_flow.py, snapshot-gex-daily.ts, vix_daily.py) and the Drive sync that already delivers TradeDash Briefs. If a writer fails, its section is omitted with a missing key — the exporter must not fabricate or carry forward a stale value.
- Maintenance: the field list lives in one place (the exporter). Adding a field is one line + one recap line. The exporter must be re-run (or re-checked) when a writer's schema changes — note the schema version in the file (`schema: 1`).
- Known data caveats to carry, not fix here: option score IC ≈ 0 (ranks/filters, not alpha — never present a score as edge); options flow side (bought vs sold) is unknown and data runs ~1 day late (display-only); SqueezeMetrics GEX is display-only; fair value is display-only and must never appear in the snapshot.

## Pass / fail

- (a) The file appears in Drive by 17:00 PT on 3 consecutive weekdays.
- (b) The evening recap run reads it and cites ≥1 number from it in "Fildi says" on each of those 3 days. (Muse-owned: the consumer is not in this repo.)
- (c) `as_of` is within 26h of the recap run each time; a file older than 26h is skipped, not quoted; a missing key is skipped. (Muse-owned.)
- (d) No secrets in the file — grep for `DATABASE_URL`, `postgres://`, `password`, `Bearer`, `api_key` returns nothing before the first ship and on every schema change.
- (e) A deliberately failed writer (kill one nightly writer for a day) omits its section rather than writing a stale value. Fixture: yesterday's IV rank plus today's puts → puts present, `iv_rank` key absent.
- (f) File size <200KB. Fixture: one ticker's strike and odds_otm match its payload.
