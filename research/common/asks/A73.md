# A73 — Schwab auth resilience: 7-day lifecycle manager, one-click re-auth, loud outage alerts

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-14
**Severity:** high (recurring manual pain + data-quality risk)

## Problem
Schwab refresh tokens die 7 days after issuance — fixed window, stamped at issue; no refresh, code, or setting extends it (verified against Schwab docs + community teardowns, Oct 2026). Full automation of the interactive re-auth (stored Schwab username/password + bot-driven login) is off the table: ToS violation, breaks on MFA/CAPTCHA/bot detection, puts brokerage credentials in the app.

Separately, the Oct 12 evening re-auth did not survive to Oct 14 (~2 days). That is NOT the 7-day wall — it is a bug or a failed token landing. Root-cause it first.

## Goals
1. Never silently lose Schwab: manage the 7-day lifecycle with early warning.
2. Make re-auth one click from the app UI (no terminal script).
3. Fail loud: Schwab down/unauthed during market hours → visible banner + log, never silent fallback.

## Scope

### 1. Diagnose the Oct 12 → 14 failure (do first)
- Read `~/.tradedash/schwab-tokens.json` on the Mac: `obtainedAt`, `lastRefreshAt`, `lastError`. Determine: did the Oct 12 re-auth tokens ever land? Is refresh failing, and with what error?
- Verify `SCHWAB_CLIENT_ID` / `SCHWAB_SECRET` (or `SCHWAB_APP_KEY` / `SCHWAB_APP_SECRET`) are present in the API server's runtime env — `schwabCredentialsConfigured()` silently yields null tokens when missing.
- Check `homedir()` mismatch: `scripts/schwab-oauth.mjs` writes tokens as the terminal user; the API server may resolve a different home (launchd/sandbox). If mismatched, unify on one path.
- Report the root cause in this row before building sections 2–4.

### 2. Seven-day lifecycle manager
- `getSchwabAuthStatus()` already computes `refreshDaysLeft` anchored on `obtainedAt` (correct — keep; Schwab does not slide the window on refresh).
- Add a scheduled check (at least daily, plus on every Schwab data fetch): if `refreshDaysLeft <= 2`, raise a persistent UI banner ("Schwab re-auth needed within N days — one click") and log a warning; if expired / refresh fails with `invalid_grant`, mark Schwab down.
- Every Schwab-backed fetch path already falls back (Schwab → Yahoo → LSEG); ensure responses and UI always carry `source` and the outage banner is visible.

### 3. One-click re-auth from the app
- Add an authenticated settings route that starts the OAuth authorization-code flow: redirect the user's browser to Schwab's authorize URL with the app's client ID + callback, handle the callback in the API server, exchange the code, and write `~/.tradedash/schwab-tokens.json` (mode 0600) with fresh `obtainedAt`.
- Keep `scripts/schwab-oauth.mjs` as fallback; the UI route is the primary path.
- After a successful re-auth, verify immediately with a cheap API call (e.g., quotes) and show green status with the new 7-day expiry date.

### 4. Outage alerting (market hours)
- When Schwab is unreachable or unauthed during 06:30–13:00 PT weekdays, surface a UI banner within 5 minutes and log it. Outside market hours, log only.
- Status endpoint must expose `configured`, `hasTokens`, `accessValid`, `refreshDaysLeft`, `obtainedAt`, `lastError` (already in `getSchwabAuthStatus()`) — wire it to the API Monitor panel, which must show the 7-day expiry date, not just "live".

## Explicitly out of scope
- Storing the Schwab username/password anywhere.
- Headless-browser or scripted login automation against Schwab's website.
- Extending the 7-day window (impossible).

## A72 interaction
The always-on server does not remove the 7-day wall, but it makes the refresh loop, the daily lifecycle check, and the warning path reliable (no missed windows because the Mac slept). Keep the lifecycle manager host-agnostic.

## Acceptance

- [ ] UI / API Monitor shows Schwab refresh-token expiry date and days-left.
