# A223 — Pilot: NautilusTrader as a study engine (re-run S064)
Filed 2026-10-20 by Muse → Claude. Source: NautilusTrader reel (repo screenshot), re-analyzed at Jamie's direction: execution capability is not the question — research infrastructure is. Verified 2026-10-20: nautechsystems/nautilus_trader real, 30.4k stars, LGPL-3.0, pip-installable (1.231.0), pushed daily. No Schwab adapter exists; live execution is out of scope by rule, not by omission.

## 1st-level analysis (Muse)
Fildi's studies are hand-rolled scripts; each S-study's data assumptions live in its header comments, and re-runs (S049 crash re-audit, S075/S076 calibrations) are archaeology. Nautilus offers: deterministic event-driven core, multiple instruments against ONE shared account (cash/margin interactions that per-name scripts silently ignore — this book ran a -$31.7k cash debit in Oct 2026), first-class options (OptionContract, multi-leg spreads, GreeksCalculator, expiry exercise module), a versioned Parquet data catalog (a study = config + strategy code + catalog snapshot), and explicit fill/slippage models that force assumptions to be declared — which fildi's study standard wants anyway.

## 2nd-level analysis
The engine is not fildi's bottleneck — historical options data is. Nautilus invents no chains; every dataset must be converted to catalog format before the engine adds value, and that conversion is the real adoption cost, paid per dataset. Its options correctness is bounded by the data and by modeling choices (early assignment of short American puts, pin risk, dividend exercise are NOT magically handled). For a one-person shop it pays off only if it becomes THE study engine — which is what this pilot decides.

## Pilot design (three gates, pre-registered)
**Subject: S064 (buy-zone puts)** — a completed study with a known verdict (≈ buy-now Sharpe, half the tail), exercising the full options path (entries, holding, exits, premium accounting) where hand-rolled scripts are most error-prone.
- **Gate 1 — conversion:** S064's dataset converts to catalog format without inventing quotes. Fail → fall back to S066 (earnings study; clean daily-bar equity data, completed verdict, tests multi-name shared-account accounting). Fail there too → finding is "fildi's constraint is chain history; effort belongs in data capture (A194-style, extended to chains)," pilot closes.
- **Gate 2 — reproduction:** same rules → trade list matches the hand-rolled run trade-for-trade, or every divergence traces to a named fill/expiry assumption; premium-kept and worst-decile tail within ±5%.
- **Gate 3 — amortization (the decision metric):** total human time (conversion + strategy code + run) vs the hand-rolled script, AND whether changing one assumption (fill at mid vs bid) is a one-line config change or a rewrite. Nautilus wins only if Gate 2 passes AND the second study would be materially cheaper than the first.

## If passed / if failed
Passed → follow-on plan: migrate the study TEMPLATE (not every old study); new options studies route through it. Failed → hand-rolled scripts stay; the pilot report names why, with the gate evidence.
