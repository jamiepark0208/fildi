# A397: options_flow.py marks a ticker-day complete after a failed/partial LSE fetch (Low)

**From → to:** Muse → Cursor · **Date:** 2026-11-10 · **Status:** planned
**Dupe check:** searched ASKS.md for options flow / A396 / fetch failure — A396 is the build row (LSE OPRA prints → options_flow_*, API, Breakdown + Feed); no row covers fetch-failure handling. Not a dupe.

## Ask

Make `options_flow.py` fail a ticker-day loudly instead of storing a partial fetch and marking the day done, so a transient LSE error is retried on the next run instead of leaving a permanent silent gap.

## Detail

**Bug (repo-watch 2026-11-10, commit 4792677, A396).** In `scripts/watchlist_sync/options_flow.py`, `fetch()` returns whatever pages succeeded when a page comes back non-200:

- `fetch()` L~: `if status != 200: print(...); return out` — `out` may hold earlier pages, or be empty if the first page failed.
- `main()` then unconditionally calls `store_prints()` + `summarize()` for that ticker-day, writing an `options_flow_daily` row.
- The next run's `done` set (`SELECT ticker FROM watchlist_sync.options_flow_daily WHERE day = %s`) skips any ticker with a daily row — so the failed day is never re-fetched for that ticker.

A transient LSE 500, or a 429 that does not carry `rows-exhausted` in the body, therefore leaves a permanent gap that is indistinguishable from a genuinely quiet day (0-print row either way). Only `RowsExhausted` and the `--max-minutes` timeout skip the summarize step today. Display-only surface, so Low — but the gap is silent and unrecoverable without manual intervention.

**Fix direction.** On any non-200 page, raise (or return a sentinel) so the ticker-day is not stored or summarized; log the ticker/day/status and move on to the next ticker. Only write the `options_flow_daily` row after a complete fetch (pages consumed until a short page, `len(rows) < PAGE`). Keep the valid-empty case working: a complete fetch with zero prints ≥ $25k still writes a 0-print row.

**Pass/fail.** Force a failure mid-fetch (e.g. point the flow URL at a 500 once): no `options_flow_daily` row for that ticker-day, and the next run re-fetches it. A genuinely quiet ticker-day still writes a 0-print row. FAIL if a failed fetch still produces a daily row.
