# A88 — Agent mission control: Jira-like tracking for agent work

**From:** Muse → Cursor
**Date:** 2026-10-14
**Severity:** medium

## Context
Jamie asked (Oct 14): he wants a view to track plans, status, progress, and comments from all AI
agents (Cursor, Claude, Muse) — enhancements, bugs, feedback — with prioritization and benefit
quantification. The settings feedback tab today is a flat list (id, message, page, createdAt — no
status, priority, assignee, comments). ASKS rows aren't surfaced in the UI at all. Research on
agent observability + mission-control patterns completed Oct 15.

## Research headline
- The space splits: observability platforms (Langfuse — Apache 2.0, self-hostable, best OSS fit;
  LangSmith, Braintrust, AgentOps) show traces/cost per call but NOT a Jira-like work board.
- Small OSS "mission control" repos implement the Kanban + activity-feed pattern, but all are
  one-person hobby projects — no dominant standard.
- Cost tracking that works: tag every LLM call with task/session/agent → SQLite ledger → dashboard
  with spend-by-task + anomaly detection. Attribute spend to git commits for a per-task ledger.
- Verdict: a SQLite cost ledger + small dashboard is worth doing; SaaS seats and a full Jira clone
  are excessive for a one-person operation.

## What to build
1. **Plans board**: surface ASKS rows in the UI — Kanban by status (open/planned/accepted/done/
   verified), with priority + estimated benefit fields added to the row format. Comments thread per
   row (agent comments land here, not lost in chat).
2. **Agent activity feed**: chronological feed of agent actions (plans filed, reviews, commits
   verified, bugs found) — sourced from the existing repo-watch/dev-loop machinery.
3. **Cost ledger**: tag LLM spend per task/agent; per-task cost vs estimated benefit view.
4. **Review queue**: human-in-the-loop inbox — items needing Jamie's decision (promotion approvals,
   priority calls), one-tap approve/defer.

## Reviews

**Claude plan 2026-10-14 (narrowed — read-only board + "needs Jamie" queue):**
1. **Source of truth stays git.** The board reads `ASKS.md` + `asks/A##.md` (parse the index line + `## Reviews` entries); it never writes them. A UI that writes repo files would fight the git bus (three agents commit to the same branch). Comments = review lines in the A## file, rendered in the card.
2. **Where:** Settings › new "Agent work" tab (next to Feedback). Columns = the existing statuses (open → planned → accepted → done → verified / declined). Card = id, title, from → to, age, last review line, `[quant]` chip. Click → renders the A## markdown.
3. **"Needs Jamie" lane (the real value):** rows whose latest review asks for a user decision (scoring promotions, A91-style "user call", spend). Detect via an explicit `**Needs Jamie:**` line agents add; no NLP guessing. Approve/decline buttons out of scope v1 (Jamie replies in chat; the agent writes the line).
4. **Drop:** priority / benefit estimates (made-up precision), activity feed (that's `git log` — show the last 10 commits with `Refs: A##` on the card instead), Langfuse / cost ledger per task. Product AI spend already lives in `ai_usage_log` + `api_usage` (Settings › API Monitor); agent session spend (Claude Code / Cursor) isn't attributable per task without new plumbing — not worth it for one user.
5. **Acceptance:** board lists every non-archived row with the correct status; the Needs Jamie lane shows exactly the rows carrying the marker; zero writes to the repo.
