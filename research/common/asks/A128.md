## Context
From @valeridoesai's reel ("4 AI agent repos"). Verified 2026-10-16:
- **DeusData/codebase-memory-mcp**: 46.7K stars, MIT, active. Local MCP server (pure C,
  no runtime) that indexes a repo into a persistent knowledge graph: functions,
  classes, imports, HTTP routes, call graphs. 17 MCP tools, 162 languages, hybrid LSP
  for TS/Python/etc. Project claims ~120x fewer tokens on code queries (3.4K vs 412K
  in their 5-query comparison — vendor number, verify independently).
- Agency Agents (msitarzewski/agency-agents, 160K stars, MIT): 232 subagent defs —
  noted, not piloted here.
- Open Montage (calesthio/OpenMontage, 68.7K stars, AGPL-3.0): agentic video
  production — side-project (Video Lab) relevance, NOT fildi; AGPL copyleft flagged.
- Graft (h0rn3t/Graft, 6 stars): "4x cheaper" claim matches the reel but repo is tiny
  and unverified — skipped deliberately.

## Why it matters
Jamie is token-conscious; Claude/Cursor re-read the fildi monorepo constantly ("don't
read node_modules or useless code"). A persistent code knowledge graph both agents
can query could cut that cost structurally — and it fits the Muse/Claude/Cursor
routing friction (agents arrive with context instead of re-discovering it).

## Proposal (Cursor pilots on Jamie's Mac)
1. Install codebase-memory-mcp as an MCP server for Claude Code (and Cursor if its
   MCP support allows); index the fildi repo (respect .gitignore — no node_modules).
2. Pilot measurement (1–2 weeks): run 10 typical agent tasks (e.g., "where is X
   computed", "trace this data flow", "what calls this route") with and without the
   MCP; record tokens used and answer quality.
3. Decision gate: keep it wired in only if measured token reduction is material
   (target: ≥50% on code-discovery queries) with no quality regression.

- No code changes to fildi from the pilot itself; it's an agent-tooling evaluation.
