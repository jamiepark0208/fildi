## The workaround architecture
Two layers, each doing what it's good at:
- **TradingView (via MCP):** charting, Pine Script indicator library (thousands of community scripts), volume profile, multi-timeframe technicals, alert webhooks.
- **fildi (existing):** Schwab chains/Greeks, scores, backtests on real options data, the book.
- Flow: TV/Pine generates or validates a technical signal → fildi checks the actual chain (strikes, IV, Greeks) → Jamie decides. Neither side replaces the other.

## Test protocol (test before any plan — Jamie's rule)
1. Cursor installs a TradingView MCP server (several exist on GitHub; pick the most-starred actively maintained one), connects it to TradingView desktop (free tier) on the Mac.
2. Exercise 1 — level cross-check: for 10 names (book + watchlist: RGTI, SPY, QQQ + 7 watchlist), pull TV's pivot/S-R levels and compare against fildi setup.py levels. Report agreement rate (levels within 0.5% count as agree) and the disagreement list.
3. Exercise 2 — Pine mining for A139: find 2–3 maintained open-source ICT Pine scripts (order blocks / FVG); can the MCP pull their code/outputs for a fildi name? Feasibility only — no porting yet.
4. Exercise 3 — alerts: create one TV alert on a watchlist name; verify a webhook/alert path can reach fildi or at least a local file. 

## Pass/fail
- Pass: MCP connects reliably, exercise 1 completes with a real agreement number, exercise 2 shows Pine code is accessible. → Muse writes the integration plan (levels QA job + A139 Pine sourcing).
- Fail: bridge is flaky, needs paid TV tier for basics, or Pine code is locked. → kill with the reason recorded.

## Use cases if it passes (Muse)
1. **Levels QA:** a weekly cross-engine check on the names that matter — catches silent level/data bugs (cf. A63 stored-bars class of bug) by disagreement, not by hope.
2. **A139 ICT sourcing:** community Pine is the reference implementation of ICT concepts; porting from tested Pine beats writing from a tier list.
3. **Independent alert channel:** TV alerts on level breaks as a second trigger source, diversifying off fildi's own scheduler.
