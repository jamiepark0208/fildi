## Model switching — design (Jamie 10-18 asked to think it through)
- **What a "model" is here:** a versioned parameter set per lane in `scorecard_params` (fund · tech · options · fair_value), one champion per lane; Model List folders use `watchlist_sync.model_params` (fit-x). Candidates beyond weights: per-decision scores (put / call / own / avoid read the same components with different weights — this row), horizon models (weekly vs 30-DTE), sizing models (S045: regime → variance, marginal), FV method sets.
- **Scope of a switch:** global — every stock at once, never per stock. Per-stock models overfit (S007: per-stock blend adds nothing; S024 sector weights fail). Per-stock *inputs* (volume nodes, IV) vary; the rule set doesn't.
- **Blast radius of the options lane:** option score → Rankings/Overall (snapshots), Friday model_recs → Model List folders, stockQuality floor gate (which names are eligible), calibration table (score→pnl buckets learned on old scores; drifts until re-learned), tilt (learn.py expectancy; unchanged), track record (split by model_version). Display tech score (Scorecard, Technicals tab) and calls are untouched — the purpose split is deliberate: display = "how does the chart look", put lane = "how will a short put do".
- **Guards now in place:** both pick paths read one loader (no silent divergence), level-matching keeps gates meaningful, before/after script, rollback command, evidence + rationale stored on the version row.
- **Not yet built (next, if wanted):** shadow mode — compute challenger scores alongside the champion every run and grade both on real expiries (`option_score_snapshots.model_version` per row), auto-report after ≥ 8 expiries / ≥ 100 picks (METHODS rule 9) before promotion; calibration table keyed by model_version.
