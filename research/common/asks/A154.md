## Detail

### Problem
`artifacts/api-server/src/lib/fund-score-engine.ts` `scoreUniverse()` (function at line 619). Inside the per-ticker metric loop:

- Lines 805–808: an optional metric with a null raw value is recorded and `continue`s. It does not enter `famAcc`.
- Line 809: `famAcc[m.family].total += m.baseIntra` runs next.
- Lines 810–818: `isExcluded(...)` then `continue`s. `present` is incremented only at line 835, after a non-null blend.

Excluded metrics raise `total` and never raise `present`. Line 858 sets family coverage to `present / total`. Line 864 passes that coverage into `shrinkToNeutral`. Line 886 can shrink the total again when confidence is low.

`isExcluded` is lines 339–369. The cases that fire the bug:

- `de` and `netDebtEbitda` — `excludeStyles: ["financial"]` at lines 197–198, and `isFinancialLike` at line 355.
- `cr` — line 357: `scoringMode === "financial"` or a bank peer-group id. Not every financial style.
- `ptbv` — line 365: excluded when the row is not financial-like. Weight is `baseIntra: 2` at line 161.
- `pFfo` — line 367: excluded when the row is not REIT-like. Weight is `baseIntra: 2.5` at line 162.

The same order bug hits every other true branch of `isExcluded` (pre-revenue peg / earnings yield / forward PE, unprofitable peg / earnings yield / EPS growth, REIT `roicwacc` / `netmgn`, distressed negative PB). A fix that special-cases five keys leaves those branches wrong. The fix is to `continue` before adding `baseIntra` to `total`.

`shrinkToNeutral` is `artifacts/api-server/src/lib/fundamentals-scoring-math.ts` lines 16 and 30–37: `score = 50 + (raw - 50) * sqrt(coverage)`, neutral constant 50.

Weight arithmetic from the `METRICS` table, not a measured book score. Safety `baseIntra` sums to 15.5 (lines 193–200). A bank that excludes `cr` + `de` + `netDebtEbitda` puts 4.5 of that into the denominator with nothing in `present`, so full remaining safety coverage caps near 11/15.5. Value `baseIntra` sums to 24.5 (lines 153–164). A non-REIT, non-financial excludes `ptbv` + `pFfo` (4.5) the same way. `sqrt` of that coverage is what pulls a high raw family score toward 50.

### Why it matters
Jamie's fundamental scorecard is an input to peer ranks and to the stock-quality leg of Model List and Options Rankings. A bank can look safer-or-weaker than it is, and every non-REIT carries a P/FFO gap in the value family, because the denominator counts metrics the scorer has already declared inapplicable. Fair value is a separate lane (S009, display-only). This bug is the fundamental coverage gate.

### Not S024
`research/studies/INDEX.md` S024 (line 35) asked whether sector weights beat one global set, and whether low coverage from nulls pushes scores to extremes. Result: keep global weights. Null-skew note there is about renormalising over inputs that are present. It did not test `isExcluded` running after the denominator add. Do not close this row by citing S024.

### Scope
Move the `isExcluded` check above the `famAcc[m.family].total += m.baseIntra` line so an excluded metric adds to neither `present` nor `total`. Leave optional-metric handling as it is. Do not retune family weights, `shrinkToNeutral`, or `scorecard_params`. No live score write in the patch until Jamie has the before/after.

### Acceptance
A unit fixture, no database and no vendor call:

- Financial / bank row: `de`, `netDebtEbitda`, and `cr` are absent from both `present` and `total`.
- Non-financial row: `ptbv` is absent from the value denominator.
- Non-REIT row: `pFfo` is absent from the value denominator.
- Optional metric with a null raw value still adds nothing (lines 805–808 stay true).
- A metric that is in-style and missing still counts in `total` and not in `present` (that shrink is the existing missing-data rule).

Then a before/after on one fixed universe (same rows, same as-of): print family coverage and total score before vs after. Jamie reads that table and says yes or no. No `scorecard_params` write in the test.
