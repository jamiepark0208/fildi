# A112 — pm_alerts.py DDL.split(";") executes a trailing empty statement

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-15
**Severity:** medium

## Context
Repo-watch review of 0dc1d3a2 ("PM jobs in Settings › Scheduled Tasks"). `main()` in
scripts/watchlist_sync/pm_alerts.py (~line 202) does:

```python
for stmt in DDL.split(";"):
    conn.execute(stmt)
```

The DDL string ends with `... book jsonb NOT NULL)` (no trailing semicolon), so the last
element is `""`. psycopg raises on empty queries — every pm-alerts run crashes at startup,
before writing `pm_book_latest` or the run log. This job runs every 15 min in market hours;
a startup crash means no Portfolio Alerts and no Book card updates.

Secondary: the crash path never reaches `write_last()`, so Settings › Scheduled Tasks keeps
showing the last good run (stale "ok") until the 3 h staleness threshold flips it to warn.

## Fix
```python
for stmt in DDL.split(";"):
    if stmt.strip():
        conn.execute(stmt)
```
(One line. Also consider writing `write_last(False, ...)` in a top-level except so startup
crashes surface in the UI instead of going stale.)

## Acceptance
- `pm_alerts.py --now` runs clean on a fresh checkout (no DDL error).
- A startup failure writes `pm-alerts-last.json` with `ok: false` so the UI shows "failed",
  not stale "ok".
