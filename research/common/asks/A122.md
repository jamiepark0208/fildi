# A122 — Muse live status on the Stage orb grid (git heartbeat)

**Status:** planned (Claude 10-16: device write OK if Jamie enables file access; git-fetch fallback)
**From:** Muse → Cursor
**Date:** 2026-10-15
**Severity:** medium

## Context
Jamie wants his Stage orb grid (Settings › Agents › Stage) to show when Muse is working,
like Claude's and Cursor's orbs do. Today the Muse orb only shows "App open / App closed"
(`pgrep -x Muse`) and last-commit time — no working state, no "doing" line.

## How the orbs work today (verified in code, 2026-10-15)
- `artifacts/api-server/src/routes/agents.ts` → `GET /api/agents/overview`.
- Claude/Cursor "working" comes from hook events in `~/.fildi/agent-events.jsonl`
  (written by `.agents/hooks/agent-event.mjs` on the Mac): working = event < 2 min old.
- Muse has no hook — it's a cloud agent; it cannot write to the Mac's disk.
  Commits already attribute correctly (GitHub noreply → muse).

## Verdict on Jamie's question ("is git push/pull too complex?")
No — git is the *simplest* reliable transport here, not overkill. The push side is one
GitHub Contents-API call (Muse already pushes .md files constantly). The pull side is
one scheduler line plus ~20 lines of route/UI code. The alternative (Muse writing to
the Mac's disk) is impossible from the cloud; a direct Mac API endpoint is unreachable
when the Mac sleeps. So: git heartbeat file.

## Design

**Muse side (operational, no code):**
- Muse PUTs `.agents/live/muse.json` on cursor/mac-dev at work-session boundaries:
  `{"agent":"muse","event":"working","detail":"<short task label>","t":"<iso>"}` on
  starting substantive work; `{"agent":"muse","event":"stop","t":"<iso>"}` when done/idle.
- Field names mirror the hook format (`t/agent/event/detail`) so the Mac side parses
  it like a hook event. Refresh `t` piggybacked on any other push Muse makes during
  an active session (briefs, plans) — no extra calls, no spam.
- This is operational data (like `commentary/` briefs), not code — within the spirit
  of the md-only push rule.

**Mac side (Cursor builds):**
1. `agents.ts` overview: read `.agents/live/muse.json` from the local checkout (ROOT);
   expose `muse: { running, live: { working, detail, t } }` where working =
   `event==="working" && Date.now()-t < 10min` (same 10-min window as Claude/Cursor).
2. Scheduler: `git pull --ff-only` on cursor/mac-dev every 5 min (or piggyback the
   existing sync job if one exists — check before adding).
3. `AgentsTab.tsx`: feed the muse orb `working: d.muse?.live?.working`; tooltip shows
   `● Working · {detail}` like the other agents; reuse the existing `attention()` pulse.
   Gray-out behavior when app closed stays as-is.

**Freshness/latency expectation:** orb lights within ~5 min of Muse starting work
(pull cadence), clears within ~10 min of Muse stopping. Good enough for a status grid.

## Edge cases
- Mac asleep/offline: checkout is stale → orb shows last known state with age in the
  tooltip ("as of Xh ago"). Never claim live when stale.
- Merge conflicts on pull: `--ff-only`; on failure, keep serving the last good read and
  surface a subtle "sync stale" note (do not break the tab).
- Muse writes nothing for quick chat replies — only substantive work sessions, to avoid
  noise.
