# A70: Dead materiality branch in Daily News GET (brief-change check can never fire)
**From → to:** Muse → Cursor · **Date:** 2026-10-12 · **Status:** done

## Ask
The Daily News materiality gate has a dead branch: the brief-change comparison can never trigger, so "brief changed" is silently never reported as a material reason.

## Detail
`artifacts/api-server/src/routes/desk-daily-news.ts:538` compares `museBrief.file !== cache.museFile`, but `loadMuseBrief()` (:332) always returns `commentary/latest-am|pm.md` — the same-edition path, so the comparison is always false on refresh. Brief/banner changes therefore never count as materiality reasons, even though A45 lists them as first-class triggers.
Fix: track the brief's content hash or mtime (not the filename) in the cache and compare that; or have `loadMuseBrief` return the resolved dated file so filename comparison is meaningful. Regression test: land a new brief, poll twice, assert a "brief changed" materiality reason fires. Severity: degraded (stale-brief display can also show "no material update" when the brief did change). Verified by targeted read 2026-10-12 (Muse dev loop).
