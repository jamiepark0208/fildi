# A255: TS put-edge factors stale-tolerant, ETF-blind, shadow-only vs Python
**From → to:** Muse → Cursor · **Date:** 2026-10-24 · **Status:** open
**Source:** Muse code review 2026-10-24, finding H4 (High).

## Ask
Bring the TypeScript put-edge loader to parity with Python — or label it shadow-only honestly. It currently claims parity its code does not have.

## Detail
Evidence: `artifacts/api-server/src/lib/put-edge-factors.ts` vs `scripts/watchlist_sync/put_edge.py`:
- TS query is `WHERE date >= (CURRENT_DATE - 120)` with no upper bound and no freshness check; Python requires the latest bar within 7 days. If LSEG history stalls, TS keeps emitting factors from weeks-old bars.
- TS has no ETF exclusion; Python excludes via parsing `lib/db/src/etf-exclusions.ts`.
- In `option-score-snapshots.ts`, `loadPutEdgeFactors(candidates)` feeds only `shadowCtx` (`ivRvUniversePct`, `volOfVolPct`); the production `stockCtx` has neither field, so live ranking never uses the TS factors.
- Header claim "same factor definitions as put_edge.py" is false in substance: Python's `pct` is a composite rank of three factors (IV/RV + vol-of-vol + put_tech); TS exposes two marginal percentiles and no put_tech.
Fix direction: add the 7-day freshness gate + ETF exclusion to the TS loader, and either wire the factors into production deliberately (with the composite definition) or rename/document them as shadow-only.

## Pass/fail
- Stale LSEG data yields no factors, not old factors (test with a stalled-history fixture).
- ETF names excluded; production-vs-shadow status of the factors is labeled in code and, if surfaced, in UI.
