## Detail
**Found (evidence: /tmp/fildi-logs, pg log, ps):**
1. Nothing started Postgres or the API/Vite at login (stack-ensure only 12:00/14:45; maintain's first fire 30 min after boot) → OpenJev 07:11, data_freshness, every DB job failed until an agent ran pg_ctl.
2. Any Postgres restart crashed the API: pg 57P01 on a pool client had no 'error' handler → uncaughtException → tsx watch waits for a file change (API down for hours).
3. Duplicate processes: each crash left a dead tsx watcher; `dev-restart.sh --if-down` checked only the port → 3 API watchers (a file edit would restart all).
4. OpenJev's daily batch held 22 GB for 10 idle min after a ~50 s run.
5. Claude's backtests ran at full priority on all cores while Jamie worked.

**Fixed (Claude):**
- `scripts/install-stack-up-launchd.sh` → LaunchAgent `com.fildi.postgres`: at login + every 5 min `dev-restart.sh --if-down` (Postgres → API → Vite, only what's missing). Tested: pg stopped → back in seconds.
- `lib/db/src/index.ts`: pool + per-client 'error' handlers. Tested: pg restart → API stays 200, 4 dropped clients logged.
- `scripts/dev-restart.sh`: single-runner lock (dead holder taken over); kills this repo's stale API watchers before starting one; `--if-down` waits 20 s for a tsx reload before replacing it. Tested: 2 concurrent runs → second skips; 1 watcher.
- `openjev_local.Server.__exit__`: a batch that started the model stops it when nobody else asked since its last request; shared/joined server keeps the 10-min watchdog. Tested both paths.
- `research/studies/PLAYBOOK.md`: runs > 1 min → `nice -n 15 env OMP_NUM_THREADS=4`.

**Rules for all agents:** start the stack only via `scripts/dev-restart.sh` (never a bare `pnpm dev`/tsx in a terminal — it bypasses the lock and pidfiles). Don't stop Postgres to test anything while the API runs without checking it recovers.
