## Ask

Fix the data-end truncation in `s178_call_grid.py` so 120/240-DTE exit values are priced to the true expiry, then re-run and correct the S178 headline numbers that rest on the biased cells.

## Detail

**Bug (repo-watch 2026-11-10, commit e839458).** In `scripts/watchlist_sync/analysis/s178_call_grid.py`, `END = 2026-11-06` (L44) is the last bar date. For a 120/240-DTE entry whose true expiry falls past `END`, `exp_i` is the last bar, not the expiry bar (L186), and the exit's remaining life is measured to the data-end bar:

- L187 guards only `dte <= 60`: entries whose calendar expiry is past `END` are skipped for 30/60 DTE, but 120/240-DTE entries proceed.
- L199: `exits = {"h21": min(i + 21, exp_i), "h63": min(i + 63, exp_i)}`.
- L207: `rem = (h[exp_i][0] - dj).days if j < exp_i else 0` — for post-2026-03 240-DTE entries, `h[exp_i][0]` is 2026-11-06, so `rem` understates the true remaining life (e.g. a June entry's h63 exit prices ~66 days of life instead of ~152). Exit call value understates time value.
- Worst case, entries within 63 trading days of data end (~2026-08-07 →): `j = exp_i`, `rem = 0`, and `price()` returns intrinsic — a 0.30Δ call is valued at ~0, i.e. pnl ≈ −100%, instead of being excluded. Same compressed-`rem` issue in the TP loop (L234).

**Size.** ~12% of 240-DTE entries have compressed `rem` at exit; ~4% are truncated to intrinsic. Estimated bias −3 to −4pp on the reported 240-DTE h63 ALL mean of −5.1% (`research/studies/data/s178_out.txt`: `240 C0.30 h63 ALL n 78814 mean -5.1`, IVLOW −1.2). True mean plausibly −1 to −2%. The 120-DTE h63 cell is affected the same way, smaller. 30/60-DTE cells are clean (L187 guard).

**What survives.** The "longer DTE NOT better" ranking vs 60-DTE (+15.3%) survives — the gap (~20pp) is far larger than the bias. What does not survive as quoted: the absolute −5.1% figure, the low-IV 240-DTE cell (−1.2/+7.9%), and the tighten pass on that cell, which uses the same biased rows.

**Fix direction.** Extend the L187 calendar-expiry guard to all DTEs (skip entries whose expiry date is past `END`), or per-exit: skip h21/h63/tp exits whose window extends past the last bar (require `j` to be a genuine calendar exit, not the last available bar). Re-run `s178_call_grid.py` (+ both `S178_TS` variants) and `s178_robust.py`, then update the S178.md table, `data/s178_out.txt`, and the BOARD "longer-dated calls" row with corrected numbers.

**Pass/fail.** Re-run on the corrected panel: 240-DTE h63 ALL mean reported for both IV variants; S178.md/BOARD numbers updated to match; the 60-vs-240 ranking re-checked on the corrected panel. FAIL if any S178.md figure still traces to the truncated panel.
