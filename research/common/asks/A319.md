## 1st-level analysis — what it is, verified not claimed

London Strategic Edge ([londonstrategicedge.com/data](https://londonstrategicedge.com/data)) is a free
market-data databank with a browser backtester, a browser ML studio, and an open-source Python
client. Muse verified on 2026-11-01:

- `lse-data` v3.0 installs clean from PyPI and imports; client surface matches the docs
  (candles, datasets, economics, dividends, company profiles, live websocket, download API).
- Free tier, from the site's own pages: 10 dataset slices per hour, up to 1,000,000 rows each,
  Parquet or CSV, price 0 GBP, one free API key. No credit card.
- Backtester: entry/exit on RSI, MACD, Bollinger, moving averages, with stop loss / take profit.
- Coverage: US/UK/Canadian stocks, forex, crypto, futures, indices, commodities, US options,
  plus macro series for 100+ countries.

Reel claims corrected against the site's own pages:

- "35 years" is a stretch for prices. Daily candles reach back to 2003 on long-listed
  instruments; the century-plus history is macro series, not equity prices.
- Dataset count differs by page: 118,000 (dashboard FAQ) vs 227,000 (ML course page). Treat
  both as marketing counts until the catalog is pulled.
- "Made by FollettCon" is unverified — nothing found connects FollettCon to this site.
- Biggest flag, from the site itself: displayed prices are "the output of our proprietary
  derivation algorithms, applied to independently sourced inputs." Derived prices, not raw
  tape. Research-grade, not golden-source.

## 2nd-level analysis — why it matters for fildi, and why research-only

Fildi has three named thin areas this lane could fill, and one hard constraint that keeps it
out of live paths:

1. Option history is thin. OptionMetrics is PERMISSION-DENIED on USC's WRDS; LSEG optlab is
   a sparse cache (~1.3 strikes/name/date); Schwab-forward is all the live option history
   there is. LSE claims options prints back to 2014.
2. Intraday bars are missing. Fildi's nightly bars are daily; intraday timing work (A219's
   narrowed VWAP timing) needs 1-minute bars fildi does not hold live.
3. Macro history is long. 14,640 macro series, some reaching back over a century — the one
   place the reel's "35 years" claim is actually conservative.
4. Constraint (non-negotiable, Jamie's market-data-quality rule): derived prices + a free
   vendor whose terms can change + a rate-limited free tier mean this lane can NEVER feed a
   live score without a golden-source validation gate first. This plan validates; it does not
   connect anything live. Any later live use is a separate row with its own validation bar.

Method note (from the companion item in the same batch — Rieseberg's ambition essay): run
this study at Depth, not Speed. Rawest material = raw LSE pulls + the Schwab/Yahoo golden
source side by side; outside judge = the agreement metrics below + Claude's summary review,
not the builder's own opinion.

## Use cases (each with why + expected value)

- **UC1 — Options-history research lane.** Pull LSE options prints (2014+) for scored-book
  names and measure strike/date coverage against LSEG optlab. Why: put-pnl harnesses
  (S-series studies) are starved for option history. Expected: coverage materially above
  optlab's ~1.3 strikes/name/date on the same names, or the lane is dropped for options.
- **UC2 — 1-minute candle backfill for intraday studies.** Pull 1m bars for a small test set
  over a fixed window and aggregate to daily closes for comparison. Why: A219's VWAP timing
  work and any future intraday study need bars fildi does not hold. Expected: a dated,
  reproducible 1m sample with a documented agreement rate vs Yahoo daily closes.
- **UC3 — Macro series for regime/macro context.** Pull a small set of macro series
  (rates, yields, econ calendar) for A314's regime program. Why: macro is the lane's longest
  and least derivation-sensitive history. Expected: 3–5 macro features with documented
  provenance, usable as research inputs only.
- **UC4 — Browser ML studio as a zero-install prototype sandbox.** Prototype one model
  (e.g., a vol forecast) in the browser and report it against a naive baseline before any
  fildi code exists. Why: the Chronos-Bolt test showed naive persistence beating a real
  model on a smooth target — prototypes must earn a fildi job by beating naive first.
  Expected: prototype + naive comparison, no fildi implementation until it beats naive.

## Downstream impact

- Research lanes only. No live score input, no UI surface, no Schwab-perimeter touch, no
  change to any fund-score, option-score, or ranking input.
- If validation passes, the follow-up (a research-lane adapter or cached-pull procedure) is
  a separate row. This row alone connects nothing.

## Upstream data dependencies + maintenance

- Free API key (Jamie's, Mac-side `.env.local` only). If the key is revoked or the vendor
  paywalls, the lane dies — cached pulls survive, fresh pulls do not.
- Rate limits: 10 slices/hour, 1M rows/slice, as observed in step 4.
- Derived-price caveat: every consumer of an LSE pull must see it; it is the reason for
  the research-only boundary.
- `lse-data` version pin; vendor API changes break the client, not fildi.

## Pass / fail bars

- **P1.** Free-key signup works and the key lives Mac-side only (no key material in repo).
- **P2.** All three samples pull (SPY daily, one options series, one macro series).
- **P3.** Agreement report published: overlapping-date coverage + close agreement rate +
  every deviation named with size. Pre-registered tolerance: ≥95% of overlapping closes
  within 0.5% of the golden source, or each miss explained (derivation method, corporate
  action, or timestamp convention).
- **P4.** Thin-area verdicts reported: options coverage vs optlab, 1m aggregation vs Yahoo
  daily, macro provenance — each with a keep/drop call.
- **P5.** Operating facts documented: observed rate limits, derived-price caveat, vendor-death
  fallback (cached pulls).
- **Stop rule.** If samples disagree with the golden source beyond P3 tolerance with no
  explanation, STOP — do not proceed to the backfill evaluation. Report the disagreement
  and close the row as failed validation.
