# A117 — Backend quant-algorithm inventory: map the classics to fildi gaps

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-15
**Severity:** medium-high

## Context
Jamie asked whether fildi needs (or already has) the backend quant-algorithm canon —
Black-Scholes, Monte Carlo, binomial tree, finite difference, OLS regression, PCA/SVD,
Cholesky, Kalman filter — and how each could enhance recommendations, fair-value analysis,
and short-term probabilistic move prediction. No systematic inventory exists: A107 covers
GS Quant's pricers, A74 covers probabilistic frameworks, but nobody has mapped each
algorithm to a fildi gap with compute-cost (big-O) awareness. This row is that map.

## Algorithm → fildi-gap mapping (to verify, not assumed)

**Pricing & Greeks**
- **Black-Scholes (closed form, O(1))**: the reference pricer/Greeks. Fildi has hand-rolled
  Greeks in `lib/options.ts` (zero tests per A83). Action: cross-validate vs BS closed form
  and vs GS Quant (A107); discrepancies become bugs.
- **Binomial tree (O(n²))**: American-style exercise. Directly relevant: deep ITM short puts
  face *early assignment* — European BS can't price that; binomial can. Use for
  assignment-risk scoring on ITM shorts (ties A92).
- **Monte Carlo (O(paths × steps))**: path-dependent payoffs and **book-level VaR /
  Expected Shortfall** for the short-premium book. Correlated MC needs Cholesky (below).
  Watch compute cost: gate path counts; precompute where possible.
- **Finite difference (PDE grid, O(grid))**: exotic/structure pricing. Likely overkill for
  fildi's vanilla book — record as evaluated-and-deferred unless a gap needs it.

**Statistics & risk factors**
- **OLS regression (O(np²))**: factor exposures, hedge ratios (e.g., beta-hedging the book),
  pairs-spread estimation. Cheap; wire into the scanner's "so what" (A81) where justified.
- **PCA / SVD (O(np²))**: decompose the book's risk into factors — are 13 short puts really
  13 bets or 1.5 factors? Eigenportfolio view of concentration risk. Feeds A74's
  book-level sizing.
- **Cholesky decomposition (O(n³), once)**: correlated random draws for multi-name Monte
  Carlo — simulate joint moves across his short-put names instead of assuming
  independence (S015 proved breaches cluster by expiry; independence is the wrong model).

**Latent-state estimation**
- **Kalman filter (O(n) per step)**: time-varying beta, pairs-spread mean-reversion state,
  volatility-regime tracking. Candidate input for short-term probabilistic moves (A74's
  P(ITM) curve) and the A115 efficiency-ratio regime filter — compare Kalman-regime vs
  ER-regime vs HMM (A56) on the same pre-registered test.

## What to build (phased)
- **Phase 1 — inventory**: for each algorithm above, record: already in fildi? (file/line),
  in GS Quant? (A107), or missing. Include big-O and realistic compute cost on fildi's
  data sizes — kill anything whose cost exceeds its evidence.
- **Phase 2 — highest-leverage builds**: binomial early-exercise scoring for ITM shorts;
  Cholesky-correlated book VaR; Kalman/ER/HMM regime bake-off on the S015 sample.
- **Phase 3 — wire-in**: only algorithms that beat baselines on pre-registered tests get
  wired into recommendations, fair value, or the P(ITM) curve. Everything else stays a
  documented evaluation.

## Token/compute guardrail (Jamie's constraint)
Every algorithm ships with a measured cost (ms/run, and where applicable tokens/run for
any LLM-in-the-loop step). Anything that can't state its cost doesn't ship. Prefer
closed-form and O(n) methods where they suffice; reserve Monte Carlo for book-level
questions that need it.
