## 1. Problem (repo-watch finding, 2026-11-05 evening run)

`challenger_posterior_for_moves()` in `scripts/watchlist_sync/learn.py` gates every challenger on a backtest posterior, but it has branches only for premium weights, `street.k`, and `severity.falling_knife`. A threshold-only proposal (the `thresholds.green_own` / `thresholds.yellow_premium` moves from live grades in `propose_params`) falls through to `return False, 0.5` — blocked every cycle, with a misleading digest line (`blocked: P=0.50`).

Before A327 stage 2 there was no posterior gate: threshold moves went straight to challenger. The gate silently retired that path — the two-cycle same-direction confirmation and the verdict-share floor in `main()` still run, but the posterior step vetoes the result. The stage-1 test (`test_a327_stage1.py:38-43`) only covers `propose_params` emitting the move, not the promotion gate, so nothing catches this.

Severity: medium. No crash, no bad promotion — the failure mode is a dead learning path: live-grade evidence can never tighten a threshold, and the digest misreports it as a failed posterior instead of an unhandled case.

## 2. Evidence (branch cursor/mac-dev @ caa1c44)

- `scripts/watchlist_sync/learn.py`, `challenger_posterior_for_moves`: `prem` → `challenger_posterior_ok`; `params == {"street.k"}` → `street_k_posterior_ok`; `params == {"severity.falling_knife"}` → `falling_knife_posterior_ok`; otherwise `return False, 0.5`. No `thresholds.*` branch.
- `scripts/watchlist_sync/learn.py`, `main()`: a threshold-only `confirmed` list hits `if not ok_post:` → `no challenger: P(better than champion)=0.50 < 0.90 posterior bar`, digest `blocked: P=0.50`.
- `scripts/watchlist_sync/learn.py`, `propose_params`: thresholds move only when live `own:21d` / `income:21d` grades have `n >= min_live_grades`, `n_weeks >= min_live_weeks`, `good < 0.5` — real evidence, currently unpromotable.
- `scripts/watchlist_sync/tests/test_a327_stage2.py:189-190` exercises `challenger_posterior_from_pool` via `apply_rationale` for premium moves only; no test calls `challenger_posterior_for_moves` with a threshold-only `confirmed`.

## 3. Fix direction

Thresholds have no backtest posterior by construction (they are set from live grades, not backtest IC). Pick one, Claude to confirm: (a) threshold-only moves skip the posterior gate — the two-cycle same-direction confirmation in `main()` is the gate, so return `(True, 1.0)` for threshold-only `confirmed`; or (b) document thresholds as never-auto-promoted and drop them from `propose_params` so the digest stops implying a posterior verdict. (a) is preferred — it restores the pre-A327 behaviour. Either way, the digest line for a blocked move must name the reason (no posterior branch), not a fake `P=0.50`.

## 4. Pass / fail

- A synthetic cycle with live grades forcing only `thresholds.green_own` (n ≥ 30, ≥ 6 weeks, good < 0.5, same direction two cycles) produces a challenger (fix a) or a digest line stating thresholds are not promoted by design (fix b) — not `blocked: P=0.50`.
- Premium / street.k / falling_knife gating unchanged: existing `test_a327_stage2.py` still passes.
- New test: `challenger_posterior_for_moves` with `confirmed = [{"param": "thresholds.green_own", ...}]` returns the documented behaviour.
