## 4. First-level analysis — what each library does for the book

- **arch / GARCH:** a forward conditional-volatility forecast. Fildi's VRP
  work compares IV against *trailing* realized vol; GARCH forecasts next
  period's vol from the vol regime, which is the right "realized" leg for a
  forward-looking gap. Separately, arch's SPA test answers the question
  fildi's study program most needs: "we tested 98 studies and picked the
  best rule — did it win by skill or by trying 98 times?" Hansen's SPA
  corrects the best-rule p-value for the whole search, which no current
  fildi gate does.
- **MAPIE / conformal:** turns any point forecast into an interval with a
  *guaranteed* coverage rate (e.g. 90% of true values fall inside, on
  average, with no distributional assumption). Fildi's forecasts are points
  with Brier scores; the book's decisions (size, strike, hold/close) are
  really interval decisions (worst-5% week, tail DD). Conformal intervals
  make those decisions calibrated instead of vibes.
- **PySR / symbolic regression:** searches for short, readable equations
  that fit a target (e.g. put edge as a function of IV, delta, momentum,
  earnings proximity, VRP gap). Unlike a black-box factor fit, a 10-token
  formula can be read, argued with, and shipped as a scorer input with a
  plain-English reason. Its failure mode is famous and must be gated:
  genetic search overfits noise beautifully, so every discovered formula
  goes through the SPA-style snooping gate (arch UC2) before it touches a
  score.

## 5. Second-level analysis — interactions, risks, order

- **Discovery without a snooping gate is banned.** PySR proposes, SPA
  disposes. The plan's build order enforces this: arch (incl. SPA) lands
  first, MAPIE second, PySR third — no formula ships before the gate exists.
- **GARCH does not contradict the Oct 24 "nothing beats VIX" verdict.**
  That verdict killed vol-*timing* signals (directional vol bets). UC1 uses
  GARCH as a *measurement* (the realized leg of the VRP gap), not a timing
  signal, and its pass bar is a forecast-accuracy shootout, not a P&L claim.
  If GARCH loses the shootout to trailing realized, UC1 dies and nothing
  else in the plan depends on it.
- **Conformal intervals do not change any live rule by themselves.**
  They change what the operator sees (interval vs point). Live-rule changes
  still need a [quant] verdict + live-weeks evidence (A250 precedent).
- **Cost/compute:** arch + MAPIE are cheap (seconds on nightly panels).
  PySR is the expensive one (genetic search, Julia runtime). Cap it:
  fixed operator set, maxsize ≤ 15, fixed random_state, nightly batch only,
  no intraday runs. Julia runtime is pinned once on the Mac; nightly jobs
  must never re-download it.
- **No live-book rule changes in this plan.** Research + display + gates
  only. Any scorer-input change is a separate [quant] verdict.

## 6. Use cases (each: why + expected value + pass/fail bar)

### arch

- **UC1 — GARCH as the forward leg of the VRP gap.** Why: the Oct 24
  finding says sell the IV-vs-realized gap, not the IV rank; trailing
  realized is backward-looking, GARCH is forward-looking. Expected value:
  a sharper gap signal for put selection and sizing. Pass bar: on
  out-of-sample data, GARCH 20-day vol forecast beats trailing-20-day
  realized on RMSE (or Diebold-Mariano p<0.10) for ≥60% of Model List names;
  else UC1 dies.
- **UC2 — SPA test as the study gate.** Why: ~98 studies, one best rule
  each — the program's biggest unmeasured risk is winner's-curse. Expected
  value: kills lucky-best rules before they reach the Model List. Pass bar:
  SPA applied retroactively to the last 10 shipped study winners; report
  how many survive at p<0.10; if zero survive, the gate still ships (the
  finding IS the value) and [quant] re-rules the survivors.
- **UC3 — GARCH vol-regime flag for sizing.** Why: size should shrink
  when forecast vol spikes. Expected value: a regime flag in the risk
  panel (forecast vol vs its own 1-year percentile). Pass bar: flag
  computed nightly for all Model List names, no new fetches, display-only
  first; sizing use needs a separate [quant] verdict.

### MAPIE

- **UC1 — Conformal intervals on put-edge / P&L forecasts.** Why: the
  book decides on tails, not means. Expected value: every forecast view
  shows a 90% interval with measured coverage. Pass bar: empirical
  coverage 0.85–0.95 on holdout AND intervals narrower than naive
  ±1.96σ; else retune (calibration-set size, model) or kill.
- **UC2 — Conformal interval on the weekly book P&L forecast.** Why:
  A250's worst-5%-week analysis is a point tail; an interval makes it a
  decision input. Pass bar: interval published alongside the weekly
  forecast for 4 consecutive weeks with coverage tracked; no live-rule
  change attached.
- **UC3 — Coverage-drift monitor.** Why: intervals that stop covering
  mean the model went stale. Expected value: a data-health signal.
  Pass bar: rolling-window realized coverage tracked; a drop below 0.80
  raises a data-health flag (display only).

### PySR

- **UC1 — Discover compact put-edge formulas.** Why: interpretable
  formulas beat black-box weights for a score the operator must defend.
  Expected value: 1–3 readable formulas (maxsize ≤ 15) that beat the
  current put-edge factor composite out-of-sample on RMSE or rank
  correlation. Pass bar: OOS win + SPA-gate pass + [quant] read of the
  formula; else UC1 dies.
- **UC2 — Discover vol-forecast formulas (GARCH shootout).** Why: if a
  10-token formula forecasts vol as well as GARCH, it is cheaper and
  explainable. Pass bar: discovered formula within 5% of GARCH RMSE
  OOS, or kill.
- **UC3 — Guardrail (not a feature): no formula ships without the SPA
  gate.** Pass bar: the gate is a code path, not a checklist — a formula
  with SPA p≥0.10 cannot be wired into any scorer input.
