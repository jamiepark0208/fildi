### Stage 1 — allowlisted snapshot
A script on the Mac writes one small file (json or csv) and pushes it only to the private location Jamie names. Each file carries the export timestamp. Contents, aggregates only:

- Row counts and `max(updated_at)` (or the table's own freshness column) for the score and market tables the audit needs.
- Scheduler / job stamps already stored: `app_config` last-run values (`artifacts/api-server/src/lib/scheduler.ts` line 52) and `enrichment_runs` (`lib/db/src/schema/index.ts` line 1686). Do not add a new history table in this row.
- Score coverage: share of names with a non-null fund score and tech score. Counts and percents, not the score vectors.
- `watchlist_sync.forecast_ledger` (`scripts/watchlist_sync/forecast_ledger.py` line 33): resolved count, open count, and the market-baseline comparison already defined on `research/studies/INDEX.md` (Brier vs `market_iv`). No question text.
- Timestamps only for Model List and options snapshots: max `model_recs.snapshot_date` (schema line 1747) and max `option_score_snapshots.as_of` (schema line 464). Same for fund and tech snapshot `as_of` if those tables are the coverage source (`fund_score_snapshots`, `tech_score_snapshots`).

Excluded by default: `stock_holdings`, `positions`, portfolio account tables, any account id column, user rows, tokens, raw env, and `.env` files. The export job fails closed if a selected column name matches account, secret, token, password, or holding.

> Hard privacy rule (Jamie, 2026-10-18): Snapshots are OK only with personal private information excluded. This is a hard requirement, not a default.
> - EXCLUDE: Robinhood account details; personal holdings/transactions at detail level; any table/column carrying quantity, cost basis, PnL, dollar amounts, balances, account identifiers, or transaction detail.
> - OK: ticker symbols alone — symbol lists with no quantity, amount, cost basis, or PnL attached.
> - Snapshot content stays: aggregate counts, data freshness, job runs, score coverage, config, model/universe lists. No personal financial detail.
>
> Builder must verify before first export:
> - [ ] PR lists every excluded table/column by name.
> - [ ] Allowlist has no table/column carrying quantity, cost basis, PnL, balances, account IDs, or transaction detail.
> - [ ] Sample snapshot has no row-level holdings/transactions data.
> - [ ] Ticker symbols, if present, appear alone with no quantities/amounts attached.
> - [ ] Export fails closed if a selected column matches quantity, cost, pnl, balance, account, secret, token, password, or holding.

### Stage 2 — SELECT-only role on the Mac
