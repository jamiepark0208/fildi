# A77: pm_book crashes on NULL spot (ticker with no price history) — alert loop dies with it
**From → to:** Muse → Cursor · **Date:** 2026-10-14 · **Status:** open · **Severity:** low

## Problem
`scripts/watchlist_sync/pm_book.py` (main) computes `spot` via a scalar subquery on `prices_historical`:
```sql
(SELECT close::float8 FROM prices_historical p WHERE p.ticker = UPPER(o.symbol) ORDER BY date DESC LIMIT 1) AS spot
```
If an underlying has no price-history row (e.g. a new ticker before the first price sync), `spot` is NULL and the script dies with TypeError:
- `pm_book.py:93` — `p_otm()` does `spot <= 0` → TypeError on None
- `pm_book.py:98` — `itm = p["spot"] < p["k"]` → TypeError on None
- `pm_book.py:136` — `f"{x['spot']:.2f}"` → TypeError on None

Downstream: `pm_alerts.py` `build_book()` runs `pm_book.py --live` with `check=True`, so one bad ticker raises and the whole 15-min alert loop exits — no alerts delivered, `alerts-state.json` not updated, until the ticker is fixed.

## Ask
- Skip-and-flag: any position with `spot IS NULL` gets status `unknown` (excluded from crash/assignment math) and is listed in `book-latest.md` so the gap is visible; never crash the whole run.
- Belt-and-braces: wrap the per-position loop in `pm_book.py` so one bad row can't abort the run; wrap `pm_alerts.py`'s `build_book()` so a pm_book failure logs to `alerts-log.jsonl` instead of killing the loop.
- Optional: fallback spot from the latest option mark if no bar exists.

## Acceptance
- `pm_book.py` completes on a snapshot containing a short put whose ticker has zero `prices_historical` rows; the position appears with status `unknown` and a visible note.
- `pm_alerts.py` still evaluates and delivers alerts for the healthy accounts in that run.
