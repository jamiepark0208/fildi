## Muse's verification (VM, Nov 7 — test before planning)

- **GLM-5.2 is REAL.** Zhipu AI (Z.ai), released to Coding Plan subscribers Jun 13, 2026, weights MIT-licensed Jun 16-17, 2026. HF `zai-org/GLM-5.2`, repo `github.com/zai-org/GLM-5`. MoE, ~753B total params, ~40B active/token.
- **1M context: CONFIRMED.** Native 1M-token input, up to 128K output (up from 200K in GLM-5.1). Caveat: the deployed window depends on the host — some platforms cap it well below 1M (e.g. 262K).
- **"Beats Claude": FALSE on the standardized benchmark.** Vendor's own numbers (Z.ai): SWE-bench Pro GLM-5.2 **62.1** vs Claude Opus 4.8 **69.2**; Terminal-Bench 2.1 81.0 vs Opus 85.0 (geodd table; harness versions differ across sources, so treat the gap as ~4–7 points, not exact). GLM wins some narrow tasks (best-harness run in Claude Code 82.7 vs 78.9; Semgrep IDOR 39% F1 ahead of the cited Claude Code result). Honest read: close to Opus on coding, wins some, loses most. "10x more capable" appears nowhere — hype.
- **"Run it completely locally": FALSE for the full model.** Full checkpoint ~1.5TB; even squeezed needs ~240GB memory — far beyond a 48GB Mac or a 16GB laptop. The reel's own install path contradicts the claim: "connect your API key, select GLM 5.2 in your model list" is API usage, not local. An independent Nov 1 explainer (WorksmartOS) makes the same correction: its demo uses OpenRouter via a paid API key — "cheap, not local."
- **"Persistent memory": UNVERIFIED as a model feature.** No source attributes persistent memory to the weights; it reads as a property of the agent harness (Zcode / Claude Code-style agent), not the model. The model is tuned for long-horizon agent runs — that is not memory.
- **Pricing (API):** $1.4/1M input, $4.4/1M output, cached input $0.26 (z.ai, Aug 2026). Pay-per-token, not free.
- **Already superseded:** BenchLM (Nov 6, 2026) marks GLM-5.2 "Superseded. Z.AI has newer models in this line: GLM-5.3." The comparison bar has also moved since the reel's June-era numbers (Claude Opus 5.5: 89.9% SWE-bench Pro; Claude Fable 5.1). Evaluate the CURRENT line (5.3 if available via API, else 5.2), not the reel's version.
- **Latency caveat:** time-to-first-token ~6.5s at 25K tokens vs ~1.9s for Opus 4.8 (Geodd) — tail latency needs testing before committing.

## Muse's analysis

**1st level — what this is.** A near-frontier open-weight coding model (MIT) with a 1M context window, available as a cheap API. For fildi the interesting shape is NOT local (impossible on the Mac) but API: a pay-per-token builder/review model that could sit in the post-Cursor seat at low cost, with a context window big enough to hold the whole repo (2,888 paths) in one shot.

**2nd level — why it matters here.** Cursor expires Dec 11, 2026 and Jamie will not renew; the build leg needs a tested $0–$20/mo replacement before December. The candidates so far are all unproven on a real fildi build: Qwen Mac-local (decision pending), DeepSeek Harness (A351, in flight), gh-aw prototype (held). GLM is a fourth candidate with two edges the others lack: (a) the cheapest credible API rate card of the four, (b) the only 1M native context, which changes what a review leg can do. Its risks are the mirror image: vendor-reported benchmarks, a fast-moving model line (5.2 already superseded), Chinese vendor (key + data routing through Z.ai/OpenRouter — Jamie's call, not assumed), and latency.
