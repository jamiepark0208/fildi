# A93 — TradingView-class chart on stock-breakdown (fix zoom, indicators, signals, IV band)

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-14
**Severity:** high (Jamie closes fildi and uses TradingView for execution timing — workflow loss)

## Context
Jamie asked (Oct 14): the stock-breakdown chart is simplistic and broken on zoom (time horizon fixed
before zoom — lines vanish). TradingView wins him over with indicator overlays, projected future
price bands, buy/sell signals, and second/minute timeframe switching. He explicitly asked for a real
benefits assessment, not dismissal as "too excessive." Web research (libraries, indicators, data
vendors, zoom architecture) + chart inventory completed Oct 15.

## Research headline
- **Stay on lightweight-charts v5** (TradingView's own OSS lib, Apache 2.0). Natively supports
  candles, multi-pane (price/volume/RSI/MACD), buy/sell markers (`createSeriesMarkers`), price lines,
  live `series.update()`. No new charting lib needed. Limits: no built-in indicators, no drawing
  tools in OSS — indicators = compute yourself, render as LineSeries.
- **Indicators**: `technicalindicators` npm (already a server dep) — RSI/MACD/Bollinger/ATR/ADX/
  Stochastic/VWAP/Ichimoku + crossUp/crossDown utils. Signals = boolean series → markers.
- **Projection**: options-implied expected-move band `EM = price × IV × √(days/365)` — market-implied,
  forward-looking, trivial compute. Highest-value overlay for a premium seller. Render as LineSeries
  into future whitespace. Cheap secondary: ATR cone; Monte Carlo fan client-side.
- **Intraday data**: 50 tickers × 1-min bars ≈ 140–200 MB/yr — trivial storage. Alpaca free (IEX,
  200 req/min) or Schwab (free with account + option chains with IV). Backfill once (~25 min),
  cache tail, lazy-load on zoom, downsample to ≤2–5k points per render.
- **Zoom architecture**: every overlay must be DATA (a series), never a drawing. Server
  `GET /bars` over base-1m + on-the-fly aggregation; client picks granularity from visible span;
  debounced visible-range refetch; prepend history scrolling left.

## Fildi today (inventory)
- `price-chart.tsx` (~600L, lightweight-charts 5.2.0): LineSeries of close only; EMA50/200 overlays;
  H/L + swing markers; support/resistance price lines. Data = live Yahoo (1D→5m, 1W→1h), not DB.
- **Zoom bug located**: `useEffect(..., [series])` calls `fitContent()` unconditionally — every
  refetch wipes zoom; no progressive history loading on zoom-out.
- Server indicator engine EXISTS (`indicators.ts` 693L: RSI/MACD/MFI/Stoch/ATR, daily bars) but the
  chart's 5m/1h bars never get indicators. Signal engine EXISTS (`intraday-entry-signals.ts`:
  OR-breakout/VWAP/pullback/sweep + RSI divergence → enter/wait/avoid) but lives in the Live tab,
  not plotted. `createSeriesMarkers` already wired — no signal source feeding it.
- Only SPY/QQQ have stored 5m bars; everything else is a live Yahoo pull (60-day ceiling).
- Zero projection bands of any kind.

## What to build (phased)
- **Phase 1 — fix zoom** (no new data): `fitContent()` only on period/ticker change; save/restore
  visible range across refetches; lazy-load older bars on zoom-out.
- **Phase 2 — indicators as series**: RSI/MACD panes below price; Bollinger/VWAP/EMA overlays;
  feed entry-signal verdicts into series-markers as buy/sell arrows. (Wiring only — math exists.)
- **Phase 3 — candles + VWAP on 1D**: CandlestickSeries (high/low already fetched); session VWAP
  from existing Finnhub aggregator; shade pre/post-market.
- **Phase 4 — IV expected-move band**: from Schwab/Polygon chain IV; two LineSeries into future
  whitespace; ATR cone as secondary.
- **Phase 5 — intraday bar service**: 1-min backfill (Alpaca or Schwab), server aggregation,
  timeframe cache, visible-range fetching.
- **Phase 6 — indicator picker**: user-togglable indicators (the "test others' published indicators"
  workflow); per-indicator signal backtest (win rate, profit factor, max drawdown).
