## Detail

### 5. Python tests for `scripts/watchlist_sync`
**Why:** The put-seller scripts (forecast ledger, dealer-gamma parse, OpenJev privacy allowlist) are not in the pnpm test gate. A red helper can ship while `pnpm typecheck` stays green.
**Cost:** Three stdlib `unittest` modules (`tests/test_forecast_ledger.py`, `tests/test_dealer_gamma.py`, `tests/test_openjev_local.py`). Imports are local modules, not MLX. Expect a few seconds on a free runner. No Postgres.
**Acceptance:** CI runs `python -m unittest tests.test_forecast_ledger tests.test_dealer_gamma tests.test_openjev_local` from `scripts/watchlist_sync` and fails the job on any assertion. A one-line break in `put_otm` or `check_state` goes red.

### 6. Build checks for api-server and stock-compare
**Why:** `tsc --noEmit` does not run `node ./build.mjs` (esbuild bundle) or `vite build`. A missing asset or bad import can typecheck and still fail the bundle Jamie runs.
**Cost:** api-server bundle is usually well under a minute. Vite production build is the slow one, often one to two minutes on a free runner, no extra services. Skip if the path filter shows neither package changed, so docs-only PRs stay fast.
**Acceptance:** `pnpm --filter @workspace/api-server build` and `pnpm --filter @workspace/stock-compare build` both exit 0. A deliberate bad import in either package fails the job.

### 7. Scoring tripwire
**Why:** Two technical scorers already disagree (`scoreTechnicalRowV2` vs `computeTechnicalRankingsV2`), and score changes need Jamie's yes plus a before/after (AGENTS.md rule 7). CI should notice the diff, not retune anything.
**Cost:** Pure fixture compare, no database and no vendor calls. Seconds. Paths to watch: `artifacts/api-server/src/lib/technical-scorer-v2.ts`, `lib/option-scoring/src/technical-rankings.ts`, `artifacts/api-server/src/lib/scorecard-params.ts`, `artifacts/api-server/src/lib/fund-score-engine.ts`, and the option-scoring weight constants. Fixed ticker fixture checked in next to the test (no live book).
**Acceptance:** If none of those paths change, the job does nothing. If any change, it prints before vs after totals for the fixture set and the job fails until the PR carries the label `needs-jamie` (or the index status says Jamie approved). The job must not write scores, weights, or `scorecard_params`.

### 8. New-file size limit (~150 lines)
**Why:** `.agents/context/workflow.md` caps a component file at 150 lines. Agents keep adding files past that. The check is for **new** files only, so the existing schema and page files do not go red.
**Cost:** A line count on added paths. Milliseconds.
**Acceptance:** A newly added file over 150 lines fails. A new file of 150 lines passes. Editing a file that is already over 150 does not fail. Generated output and `lib/db/src/schema/` stay excluded so a migration-sized schema file is not blocked by this rule. The component cap is the rule being matched; Claude can narrow the glob to `artifacts/stock-compare/src/components/` if a repo-wide cap is too blunt.
