## What's worth borrowing (verified from project description)
- **Full-lifecycle pipeline**: research → position sizing → ongoing monitoring → risk
  management → exit decisions. Fildi has entries (scanner) and monitoring (alerts) but no
  unified lifecycle view — the exit-decision leg is the gap (ties to A92's assignment-aware
  track record: when to close/roll is currently ad hoc).
- **Approval-gate pattern**: OpenAlice requires explicit user approval before any execution,
  with version history and safety checks on every action. This is the control pattern fildi's
  agent features should copy — suggest-only, human confirms.
- **Multi-asset workspace**: unified view across asset classes (equities + macro at minimum
  for the put book; crypto/commodities later if ever).

## What to build (phased)
- **Phase 1 — teardown**: read OpenAlice's architecture (lifecycle stages, monitoring loop,
  exit-decision logic, approval gates); document which stages map to fildi gaps.
- **Phase 2 — lifecycle view**: design a position-lifecycle panel (research → open →
  monitor → exit-decision) for the put book, suggest-only, with explicit approval on any
  action. No execution wiring.
- **Phase 3 — exit-decision logic**: the highest-value borrow — systematic exit rules
  (profit-take, roll triggers, assignment defense) feeding the existing alerts.
