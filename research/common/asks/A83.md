## Findings (inventory summary)

**Duplicated logic**
- `lib/retry.ts` (`withRetry` + jitter) vs `lib/http-client.ts` (own private `jitter()` + `sleep()`):
  two jitter implementations, same thundering-herd comment. Merge into http-client.
- `lib/technical-scorer-v2.ts` (api-server) vs `lib/option-scoring/src/technical-rankings.ts`
  (repo-root package): two technical scorers (RSI/MFI/MACD/ATR weights vs tier system). Pick one.
- `src/scripts/backfill-*.ts`: 20 backfill scripts, near-certain boilerplate duplication → shared
  backfill harness.
- `src/middlewares/.gitkeep`: dead dir next to real `src/middleware/` — delete.

**God files (>400L)** — split boundaries:
- `lib/fund-score-engine.ts` 970L/28 exports → pure math (partly done) / DB IO / orchestration.
- `lib/model-track-record.ts` 862L + 3 serial for+await loops → EB math / path-risk / persistence;
  parallelize loops with concurrency cap.
- `lib/indicators.ts` 694L/14 exports → indicator math / source-merge (hosts mergeSchwabYahoo).
- `lib/scheduler.ts` 641L/15 exports → job definitions / catchup / registry.
- `lib/options.ts` 499L/9 exports → pure Greeks math (testable) / IO; also batch the serial
  per-expiry `fetchChain` loop.
- `lib/regime-classifier.ts` 472L, `lib/intraday-regime.ts` 443L — check overlap before splitting.

**Inefficient patterns**
- `lib/fmp-client.ts`: serial fetch + 300ms sleep loop — biggest quota/latency win. Register FMP in
  `PROVIDER_LIMITS` and use bounded concurrency.
- No date library (no date-fns/dayjs/luxon); date math hand-rolled across `usage-date.ts`,
  `market-hours.ts`, `daysUntil` — one date util; verify ET handling consistent.
- 64 scripts in `src/scripts/` + 109 in `scripts/` — audit which still run; several look one-shot.

**Inconsistencies**
- Logging: `console.log` in yahoo-client.ts vs pino `logger` standard — codemod.
- Error handling: `.catch(() => null)` in fmp-client swallows failures silently — at least log.
- `as any` casts on external payloads (`analyst-events.ts`, `yahoo-client.ts`); zod is a dependency
  but fmp-client has zero zod imports — validate client payloads.

**Test gaps (riskiest first)**: `lib/options.ts` Greeks (zero tests), `fund-score-engine.ts`,
`indicators.ts`, `regime-classifier.ts`, `intraday-regime.ts`, `portfolio-risk.ts`,
`buying-power.ts`, `ticker-pnl.ts`, `iv-rank-backtest.ts`, `enrich-and-merge.ts`, `live-quote.ts`.
108 of 134 lib files untested.
