## Ask
Repo-watch on the 11-17 Today batch (c6f68d7) found two accuracy nits in the new bottom checklist (`artifacts/api-server/src/routes/strategies.ts`, `bottomChecklist()`):

1. HY OAS percentile window is mislabeled. The `credit` check computes `pct` as the percentile of the latest HY OAS value over ALL rows in `watchlist_sync.macro_daily` (hy_oas backfilled from 2010 via `scripts/watchlist_sync/vix_daily.py::load_hy_oas`), but the `why` text says "…th percentile of the last 3 years". Fix: either restrict the percentile query to the last 3 years (to match the label) or change the label to the true window. Prefer restricting the query — a 3y percentile is the more useful read, and the 2020 panic reference stays as context.
2. Earnings-reaction check says "first session pending" when the report date is a non-trading day. In the `cat-<ticker>` branch, `pre` is only set when `rows[0].date === rows[0].rd`; if `report_date` falls on a weekend/holiday, `rows[0].date > rd`, so `pre` is null and the row reports pending even though post-report sessions exist. Fix: use the last close on or before `rd` as the pre-report price (e.g. `p.date <= rd ORDER BY date DESC LIMIT 1`) instead of requiring an exact-date match.
