## 1. Problem (repo-watch finding, 2026-11-04 evening run)

Settings › Indicators and the two charts disagree about defaults, in two ways:

1. **Fresh profile: Settings shows all-off while charts show defaults on.** `IndicatorsTab.tsx:76` calls `getDefaultIndicators()` with no fallback, so with no `fildi_default_indicators` key it renders every checkbox unchecked — while the Breakdown chart defaults to EM+EMA and the Live chart to UT+ST.
2. **The Live chart never reads Settings defaults at all.** `regime-session-chart.tsx:389-396` keeps its own key (`live.chartIndicators`, fallback `["ut", "st"]`) and never reads `fildi_default_indicators` nor listens for the `fildi:default-indicators` event. So touching Settings › Indicators changes nothing on the Live chart, contradicting bfc3f068b's "keep each chart's own default … until Settings › Indicators is touched" — for Live, touching Settings is a no-op.

Severity: low. No data or scoring impact; defaults on both charts are sensible. It is a UX-truth bug: the Settings tab claims to control defaults it does not control on one chart, and misreports the current state on a fresh profile.

## 2. Evidence (branch cursor/mac-dev @ 40f4746f2)

- `artifacts/stock-compare/src/components/settings/IndicatorsTab.tsx:76` — `useState(() => getDefaultIndicators())`; `indicator-defaults.ts` returns `[]` when the key is absent and no fallback is passed.
- `artifacts/stock-compare/src/components/price-chart.tsx:876` — `getDefaultIndicators(["em", "ema"])` (Breakdown default).
- `artifacts/stock-compare/src/components/live/regime-session-chart.tsx:389-396` — own `live.chartIndicators` key, fallback `["ut", "st"]`; no reference to `fildi_default_indicators` anywhere in the file.
- `artifacts/stock-compare/src/lib/indicator-defaults.ts` — `KEY = "fildi_default_indicators"`, `EVT = "fildi:default-indicators"`.

## 3. Fix direction

Pick one source of truth, don't patch around it: either (a) the Live chart reads `getDefaultIndicators(["ut", "st"])` (and subscribes to the event for live updates) and the Settings tab initialises from the per-chart fallbacks, or (b) document/rename Settings › Indicators as Breakdown-chart-only. (a) is preferred — it matches what the tab already promises.

## 4. Pass / fail

- Fresh profile (no keys): Settings › Indicators checkboxes match what the charts actually show (EM+EMA on Breakdown, UT+ST on Live).
- Toggle an indicator in Settings, then open each chart: both charts' defaults reflect the toggle (on next mount at minimum; live via event if implemented).
- Existing stored keys keep working: a user with `live.chartIndicators` set is migrated or honoured, not silently reset.
