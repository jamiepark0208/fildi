# A222 — [quant] Qlib underlying-ranking study: downside-label model as a score factor
Filed 2026-10-20 by Muse → Claude. Source: @arwazaz_ carousel (Colab + Qlib/FinRL/TensorTrade), re-analyzed at Jamie's direction. Tools verified by Muse 2026-10-20: microsoft/qlib real and maintained (49.5k stars, MIT, pyqlib 0.9.7 pip-installable).

## 1st-level analysis (Muse)
Underlying selection is fildi's upstream equity problem: every downstream number (premium kept, assignment rate, tail loss) is conditioned on which names puts were sold on. Today that ranking is hand-weighted scores. Cross-sectional ranking from daily data is exactly Qlib's job (Alpha158 features computable from OHLCV alone; LightGBM workhorse; honest published baselines: Rank IC ~0.04–0.05 on CSI300 — expect 0.02–0.04 on US names).

## 2nd-level analysis
Do NOT predict forward return — wrong target for a put seller. The label is downside-shaped: P(name drops >= X% within the DTE window), or forward return minus a worst-decile penalty (expected-shortfall flavor). Fildi's options-informed fields (IV rank history, skew S075, chain snapshots, GEX S034) export as extra per-name daily features — that is where a fildi-specific edge would live, not in stock features alone. Output enters fildi scores as ONE versioned factor column with its live IC tracked — never a replacement for the score. This study also answers two gaps from the 20-strategy map: Cross-Sectional Alpha (the baseline to beat is the CURRENT score's rank correlation with realized outcomes) and Machine Learning Alpha (this is the gated ML entry-ranking test).

## Use cases (Claude: propose additional ones before running)
1. **Put-underlying ranking:** downside-risk rank feeds entry selection (avoid the names whose drops cause assignments).
2. **Assigned-share management:** rank on held shares informs keep-and-write-calls vs exit; Qlib's portfolio layer can backtest covered-call strike/exit rules.
3. **Long-sleeve optionality:** if fildi ever runs a long equity book, this pipeline is its selection engine with zero rework.

## Study design (pre-registered)
- Universe: the BROADEST set fildi's bars cover (not just the watchlist — small universes make Rank IC noise and LightGBM memorizes), point-in-time as-of-date membership (no survivorship cheat), then rank watchlist names out of that model.
- Walk-forward folds; label windows strictly inside training folds (leakage in the custom label code is the known trap).
- Pass: held-out Rank IC on the downside label beats the current score's rank correlation with realized assignment/drawdown outcomes; AND top-vs-bottom quintile spread in realized DTE-window drawdowns is material (>= 1.5x). Modest bar on purpose: US Rank IC 0.02–0.04 earns a modest factor weight, not control.
- Fail: fildi keeps a benchmark harness + converter; no factor ships.
- Integration if passed: offline batch on the Mac — CSV export → Qlib dump_bin, weekly retrain, rank parquet imported as a factor column. Nothing in the live path depends on it. Install note: LightGBM on Apple Silicon needs `brew install libomp` (Qlib README flags it).
