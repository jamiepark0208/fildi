## Detail

**Bug (repo-watch 2026-11-10, commit e839458).** `scripts/watchlist_sync/analysis/s178_call_grid.py` reads the IV surface at import time:

- `SURF = json.loads((HERE.parent / "out" / "opt" / "s178_surface.json").read_text())` (L40, module level, import time)

but `scripts/watchlist_sync/out/opt/s178_surface.json` is not on branch `cursor/mac-dev` (contents API 404; no commit ever touched the path). `out/opt/` is not gitignored — other files there (e.g. `A276-S124-packet.md`) are tracked — so the file was generated locally by `s178_surface_calib.py` and never committed. On any machine without that local artifact, `import s178_call_grid` raises `FileNotFoundError`; `s178_robust.py` fails the same way (it imports `SETS, OUTP, SPLIT, month_t` from `s178_call_grid`). Nothing in production imports these scripts, so impact is study reproducibility only — nobody can re-run S178 (including the A388 re-run) without first running the calibration step against the LSEG quote tables.

**Fix direction.** Either commit the generated `s178_surface.json` alongside the scripts (preferred — it is the study's key input, small JSON), or move the load into `main()`/`load()` with a clear error telling the user to run `s178_surface_calib.py` first. Do not silently regenerate it at import (the calibration reads ~770k quotes).

**Pass/fail.** Fresh clone of `cursor/mac-dev`: `python -c "import sys; sys.path.insert(0, 'scripts/watchlist_sync/analysis'); import s178_call_grid"` succeeds (or fails with the explicit run-calibration-first message, if the lazy-load route is chosen).
