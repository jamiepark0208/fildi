# A95 — Analyst revision breadth: sector upgrade/downgrade timeline

**Status:** open
**From:** Muse → Cursor
**Date:** 2026-10-14
**Severity:** medium

## Context
Jamie asked (Oct 14): a view of all recent upgrades/downgrades — x-axis as date, dots for tickers —
to see whether sectors are broadly being upgraded or downgraded, tracked historically. He correctly
suspected magnitude-weighting is impossible (not all revisions carry targets). Inventory completed
Oct 15.

## What the data supports
- `analyst_events` (ticker, firm, action, eventDate) + `ticker_registry.sector` → a weekly
  **upgrades − downgrades diffusion series per sector** is a straightforward aggregation. The
  dot-timeline works: x-axis = date, dots = events, colored by sector; diffusion line per sector.
- **Count-based only**: price targets exist solely on `fmp-target` rows (no grade info); upgrade/
  downgrade rows never carry targets. Magnitude weighting is impossible — diffusion math only.
- **Thin history**: 365-day cap, per-firm dedup, Yahoo per-ticker history only weeks–months deep.
  Forward accumulation from the backfill is the realistic path; no retroactive depth.
- Exclude or down-weight initiate/maintain/reiterate rows in the diffusion math.

## What to build
1. **Sector×week rollup**: aggregation over `analyst_events` → table or materialized view
   {sector, week, upgrades, downgrades, diffusion}; API route serving it (nothing cross-ticker
   exists today — all reads are per-ticker).
2. **Timeline UI**: per-sector diffusion lines (upgrades − downgrades, rolling 4-week) + event dots
   (x = date, dot = ticker action, hover = firm + grade change). Sector filter; watchlist-only toggle.
3. **Forward fill**: keep the existing backfill running so history deepens from here.

## Acceptance
- [ ] Sector diffusion timeline renders for all tracked sectors; dots hover to firm/grade/date.
- [ ] Initiate/maintain/reiterate excluded from diffusion (documented).
- [ ] "Count-based only — no magnitude" labeled on the view (honesty convention).
