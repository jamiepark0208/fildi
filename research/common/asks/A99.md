# A99 — Data confidence: every number shows source, freshness, and quality

**Status:** planned, narrowed
**From:** Muse → Cursor
**Date:** 2026-10-14
**Severity:** medium-high (Jamie can't tell how "good" any datapoint is)

## Context
Jamie asked (Oct 14): with overlapping pipelines, formulas, and adjustments, he can't tell for any
UI number (fundamental score, P/E, IV rank, growth, assumption metrics) how good it is, where it's
sourced from, or when last updated. Web research (quality scoring, provenance UX) + provenance
inventory completed Oct 15.

## Research headline
- **Metadata contract per metric**: {source, observed_at, period, kind: actual/estimated/
  preliminary/modeled, formula, confidence}. Airbnb's 0–100 DQ Score is the precedent (bands +
  per-dimension sub-scores, formula published, weights by business risk not equal averages).
- **Classify every value**: CONFIRMED / LIVE_PREVIEW / STALE / INVALID. Stale keeps the last-known
  number with a visible age label and is **excluded from rankings**; never render a plausible-looking
  number for invalid/missing data.
- **Uncertainty display**: CIs or High/Medium/Low from backtested hit rates for modeled numbers;
  "E" badges for estimates (Morningstar rule: estimates explicitly noted in the citation).
- **Lineage tooltip**: "Computed from: EPS $4.21 (10-Q 2026-Q3, actual) ÷ price $187.40 (live)" with
  each input's own freshness dot.

## Fildi today (inventory)
- **Provenance machinery exists but is invisible**: `field_provenance` (winning source, divergent,
  override, fetchedAt) + `GET /api/fundamentals/provenance/:ticker` — only surfaced in the Stock DB
  admin grid. Breakdown views show no source/vintage on most numbers.
- **Scores have vintage stored, not shown**: snapshots carry `computedAt` + `inputsDigest` — the UI
  never answers "this score was computed from 6-day-old fundamentals."
- **Danger cases**: IV rank is a realized-vol proxy (schema warns) with no UI warning; estimates
  (EPS, growth) carry no estimated-vs-actual badge; staleness lives in Settings/admin only.

## What to build (phased)
- **Phase 1 — inline provenance**: source badge + as-of + freshness dot on every breakdown metric,
  reusing the existing provenance API (tooltip component, no new plumbing). "E" badge on estimates.
- **Phase 2 — input vintage on scores**: show "computed {date} from inputs as of {date}" on fund/
  tech/option/fair-value scores; stale-input scores get the STALE classification.
- **Phase 3 — quality score**: per-metric 0–100 (freshness, source rank, divergence, coverage) with
  named bands and published formula; High/Medium/Low from hit rates for modeled numbers.
- **Phase 4 — proxy warnings**: IV rank and any proxied metric get an explicit proxy label.
