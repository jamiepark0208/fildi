# A275: Surface snapshot age on DB-only option surfaces (Live table first)
**From → to:** Muse → Cursor · **Date:** 2026-10-26 · **Status:** planned (Claude 10-26)
**Dupe check:** ASKS.md + asks/ searched. A256 added the relaxed flag + the DB-only comment but no age display. A215 (source/last-updated tooltip) is a different surface (fundamentals) — reuse its pattern, not its build. No row surfaces rankings snapshot age.
**Moves:** ops (data confidence — the guard that makes DB-only safe)

## Thesis
The Live table is DB-only by design: it renders nightly option-ranking snapshots. But its hook discards the snapshot timestamp — so if the nightly snapshot job skips or fails, Jamie decides put sales off silently stale premiums with nothing on screen saying so. DB-only without an age label is a silent-staleness machine. A274 makes DB-only real; this row makes it visibly safe.

## Why now
- A274 (this loop) turns the Live table's DB-only claim from false to true. The day that lands is the day a stale snapshot becomes the *only* data on screen — the age label must land with it, not later.
- Repo-watch 2026-10-25 flagged exactly this: "Live table now DB-only; fallback removed, so stale snapshots = stale/empty rows."

## Evidence (read 2026-10-26, branch cursor/mac-dev)
- `artifacts/api-server/src/routes/options.ts:76,86`: the route already returns `asOf`/`computedAt` alongside rows — the data exists server-side.
- `artifacts/stock-compare/src/hooks/use-top-options.ts:94-95`: the lite hook types the response as `{ rankings }` only and fetches with `livePrices=0` — `asOf`/`computedAt` are dropped in transit.
- `artifacts/stock-compare/src/components/live/top-options-table.tsx` (121 lines): no `asOf`, `computedAt`, snapshot, or stale text anywhere.

## What changes (plan-level, never code)
1. Plumb `asOf`/`computedAt` from the rankings response through the lite hook to the Live table; render a compact "snapshot as of <date/time>" label on the table.
2. Add a stale badge when the snapshot is older than the nightly cadence allows (builder sets the threshold from the actual snapshot-job cadence — nightly, so roughly >30h, not an invented number — and names the job it keys off).
3. Apply the same pattern to the Rankings page if it also drops `asOf` (builder checks; if it already shows it, note that and skip).
4. Display only: no score, snapshot-content, or ranking change.

## Use cases + expected results
- UC1: Jamie opens the Live table on a normal morning → sees "snapshot as of <today>" and trades with confidence in the data's age.
- UC2: Nightly snapshot job fails → table shows a stale badge instead of yesterday's premiums presented as today's. Failure mode becomes visible before any put decision, not after.

## Pass/fail
- [ ] Live table shows snapshot as-of on every load, sourced from the response (not a hardcoded date).
- [ ] A fixture with an old `asOf` renders the stale badge; a fresh fixture does not.
- [ ] Premium/strike/score values unchanged by the change; no snapshot-row content change.
- [ ] Rankings page checked: age shown or a note that it already shows it.

## Risks
- Timezone confusion on the label — use the ET trading-day key convention already used elsewhere (e.g. portfolio-risk cutoff), and show date + time.
- Badge noise if the nightly job's timing varies — threshold keyed to the real job cadence, not a guess, mitigates this.
