# A321 — FinBERT real-headline validation: adopt as triage or drop
**From → to:** Muse → Cursor · **Date:** 2026-11-02 · **Status:** planned

## Ask
Finish the FinBERT evaluation that stopped at a 14-headline toy test, and end it with a verdict: adopt as a headline-triage input (with a settings catalog row) or drop the thread for good. Same limbo-closure rule as A320.

## 1st-level analysis (what happened)
- Oct 26 VM test: 14 headlines, ~0.15s each, runs fast and light on CPU. 10 sensible, 3 wrong/overconfident, 1 frame-ambiguous. Verdict then: triage number only, never a standalone trigger — it has no frame for who a headline is good for.
- The named next test — real fildi headlines checked against price moves — was proposed and never run. That is the gap this row closes.
- License constraint, fixed: FinBERT weights are CC BY-NC-SA 4.0, which blocks monetized use. That flag stands for A233 regardless of outcome; adoption here means research/triage only, never a sold signal.

## 2nd-level analysis (why it matters)
- Headline triage is the one FinBERT job with a plausible edge: fildi already ingests desk headlines (OpenJev labels) and a Daily News panel that appends only material desk adds. A cheap sentiment score could speed triage — if it survives contact with real headlines and real moves.
- If it fails on real data, the thread closes with evidence instead of lingering as "maybe useful."
- Either way the row ends in a settings catalog row (adopted triage input, or a recorded drop).

## Use cases
- **UC1 — Desk-headline triage.** Score every ingested desk headline and show score + label next to it in the Daily News panel, paired with the named company's price action. Why: the Oct 26 failure mode was missing frame (who is it good for); name context + price action supply the frame. Expected value: faster triage of what matters to the book, with the pairing rule suppressing the overconfident-wrong class.
- **UC2 — Earnings-headline check.** Score pre/post-print headlines and compare against the print-day move. Why: tests whether sentiment adds anything beyond the price move itself in the one window where headlines matter most. Expected value: a second input to the earnings-note pipeline, or proof it adds nothing.
- **UC3 — News-gap tag enrichment.** FinBERT score as one input to the put-board "moves with" news-gap tag (A316) — a tiebreak/flag only, never the trigger. Why: the tag currently fires on price/news coincidence; a sentiment sign could cut false tags. Expected value: fewer false news-gap tags, or evidence the score doesn't help there either.

## Steps
0. Build the headline×move dataset from fildi ingested headlines + golden-source prices (Mac/DB export, not toy headlines). Include the Oct 26 failure classes as a labeled subset.
1. Measure: directional agreement (does the FinBERT sign match the subsequent move's sign?) with a stated confidence interval, plus the overconfident-wrong rate, plus the same two numbers under the pairing rule (score shown only with name context + price action; paired rule must suppress at least 2 of the 3 Oct 26 failure classes).
2. Pass gate: directional agreement better than chance AND the pairing rule demonstrably cuts the failure rate. If either fails: close as failed validation, write the drop verdict + catalog row ("tested, not adopted"), stop. No integration work.
3. If the gate passes: wire FinBERT as a triage field on ingested headlines (score + label + pairing rule), shown in the Daily News panel. Never a standalone trigger, never a score input. Add the settings catalog row (name, plan: local/$0, feeds: headline triage, limit: none, license note: CC BY-NC-SA, research/triage only).
4. Reviewing agent (Claude, ≤20-line summary when pool recovers): propose 2+ additional use cases from these worked examples before the row closes. Grok may red-team the pass gate.

## Pass / fail bars
- **P1.** Headline×move dataset built from real fildi headlines (not toy data) with agreement + failure-rate numbers reported.
- **P2.** Adopt requires beating chance on direction AND the pairing rule cutting the failure rate; both on real data.
- **P3.** On adopt: triage field live in the Daily News panel + catalog row visible in Settings. On drop: drop verdict + catalog row recorded, no integration code.
- **Stop rule.** A win on toy headlines that fails on real headlines → drop, not "promising."
