# A132 teardown: FinceptTerminal vs fildi (Muse 2026-10-18)

**Verdict: steal 2 ideas, park 1, skip the rest.** Fincept is a broad retail terminal; fildi is a put-seller's copilot. Most of Fincept's surface doesn't transfer.

## Steal-list (scored 1–5 for put-seller value)

### 1. Portfolio-level VaR + risk analytics — STEAL (5/5)
Fincept has VaR/Sharpe/portfolio optimization in its QuantLib suite. Fildi has A136 (pre-trade risk gate: "bot that only says no" badges) but **no portfolio-level "how much do I lose if everything goes wrong" number**. For a put seller running multiple short puts, portfolio VaR (e.g., "95% VaR = $X if all underlyings drop 2σ") is the single most useful risk number and fildi doesn't have it. Build: medium — VaR math is standard (parametric or historical from `prices_historical`), no new data needed. This is a real gap, not a nice-to-have.

### 2. Visual node editor for custom workflows — PARK (3/5)
Fincept's ReactFlow node editor lets users wire data → transforms → actions visually. Fildi's Stage is agent-status, not user-workflow. A node editor could let Jamie build "when X, do Y" pipelines (e.g., "when IV rank > 80 and earnings > 14d out, flag for put sale"). But: high build cost (ReactFlow + execution engine), and fildi's agent framework already does automation. Park until a concrete workflow need emerges — don't build a generic editor hoping users invent uses.

### 3. News sentiment overlay — SKIP (2/5)
Fincept aggregates 560 articles/53 feeds with sentiment. Fildi already has Daily News + email ingest + materiality gate (A45/A70). Sentiment scores are a commodity (FMP has them); the put-seller question isn't "is news positive" but "does this change my position risk" — which A79 (earnings risk) and A136 (risk gate) already address. No incremental value.

## Don't-adopt list (kill reasons)

- **37 AI persona agents (Buffett/Graham/Lynch):** gimmick. Fildi's A85 pundit tracker does the serious version (scored, checkable calls). Personas are entertainment, not edge. SKIP.
- **16 broker integrations:** fildi is read-only by design; Jamie trades manually. N/A. SKIP.
- **Paper-trading engine:** fildi has `backtest_puts.py` for strategy testing. A paper engine adds live-sim complexity without a put-seller use case. SKIP.
- **100+ data connectors:** fildi's data stack (Schwab/Yahoo/FMP/Polygon/LSEG) covers the put-seller need. Specific gaps (FRED, IMF) are already in the briefs or A85. No wholesale connector spree. SKIP.
- **Maritime/geopolitical tracking:** N/A for selling puts. SKIP.
- **AI Quant Lab (ML/RL factor discovery):** overlaps A120's X/Y engine (already planned). Don't duplicate. SKIP.
- **C++20/Qt6 desktop app:** different stack, different audience. Fildi is web. N/A. SKIP.
