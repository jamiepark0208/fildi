## What Pinchtab is (verified from repo)
- Standalone Go HTTP server giving AI agents direct control over Chrome: navigate, extract
  structured content, interact with DOM — via curl, CLI, MCP server, or agent skill.
- **Token-efficient**: ~800 tokens/page with text extraction (5–13x cheaper than screenshots);
  accessibility-DOM element refs (stable across filter changes); smart diff mode.
- Ships an agent skill auto-installed into `~/.claude/skills`, `~/.cursor/skills`,
  `~/.codex/skills` etc. on install, with staleness detection.
- Stealth mode, persistent sessions/profiles, multi-instance orchestration, site-audit mode.
- Security: local-first by default (binds 127.0.0.1, IDPI allowlist restricts to local sites
  until explicitly widened) — matches Jamie's security posture. Not for public-internet exposure.

## Why it fits (and how it differs from A104)
- A104 (Lightpanda) swaps the browser **engine** for RAM savings. Pinchtab is the **control
  layer** driving Chrome — the win here is **tokens, not RAM**: 800-token page snapshots vs
  screenshots for every agent web-read. Jamie is token-conscious; his agents' web research is
  exactly the workload this cheapens.
- Complementary, not competing: evaluate independently; they can stack later.

## What to build (phased)
- **Phase 1 — pilot on Cursor**: install Pinchtab locally (Mac), let it install its Cursor
  skill, run a fixed set of web-research tasks (e.g., 5 consulting-outlook page extractions
  for A85 Tier 4). Measure: tokens consumed vs the current screenshot/DOM-dump approach,
  output correctness.
- **Phase 2 — adopt on token win**: if snapshots are correct at a fraction of the tokens,
  make Pinchtab the default web-read path for agent research tasks. Keep telemetry posture
  reviewed; local-only binding mandatory.
- **Phase 3 — fildi scrapers**: evaluate Pinchtab's HTTP API as the extraction layer for
  the JS-rendered sources from A104's inventory (alternative to raw CDP).
