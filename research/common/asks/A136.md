## Why it matters
Jamie's book is live short premium. Every new short-put idea should pass a risk
gate BEFORE he sizes it: max 1% risk/trade, ATR-based sizing sanity, correlation
vs existing book, portfolio-level drawdown halt (10%), earnings inside DTE window
(ties A79), negative-gamma regime (ties A134). Today that check is manual.

## Proposal (Cursor builds)
1. Risk-gate module: given a candidate trade (ticker, strike, DTE, premium) +
   current book state, return PASS/FAIL with reasons.
2. Checks (v1): position size vs 1%-of-equity cap; delta-adjusted exposure vs
   existing positions in same underlying/sector (correlation filter); earnings or
   FOMC/CPI inside the DTE window (reuse A79 calendar); portfolio drawdown vs 10%
   halt; GEX regime flag (reuse A134 when built).
3. UI: every scanner/idea card gets a risk badge (green/yellow/red) with the
   failed checks listed. Red = blocked from one-click worksheets, never from
   Jamie's own judgment — he can override, and overrides are logged (feeds the
   A80 thesis tracker: did overrides help or hurt?).
4. Backtest the gate: apply it historically to the 1,513 Robinhood trades —
   would it have filtered the losers? Preregister per A131.

## Backtest protocol (Muse prep, 2026-10-20 — so the validation runs once, clean)
Jamie asked what "the A136 backtest" concretely is. This is it:
- **Question:** do the gate's red flags predict bad trades? A gate whose flags don't predict losses is decoration.
- **Dataset:** every historical candidate the gate can be re-run on — pm_alerts "what-if" rows + the book's actual short-put entries (ticker, strike, DTE, premium, entry date) — with realized outcomes (premium kept %, assigned Y/N, max adverse move inside DTE).
- **Method:** re-run the gate rules (size cap, earnings-in-window, GEX state, drawdown state) as of each entry date, using only data available that day. Split entries flagged vs unflagged.
- **Pass bar (pre-registered):** flagged entries show ≥1.5× the loss/assignment rate of unflagged, AND the gate would have blocked ≤30% of the profitable entries. Fail either → the failing check gets tuned or dropped; a gate that blocks winners and passes losers is worse than no gate.
- **Overrides:** Jamie's logged overrides are the most informative rows — score them separately (did overriding the gate make or lose money?).
- Claude: propose any additional scoring angle in review, then run.
