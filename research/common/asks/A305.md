# A305: One tab system, one type system — Live-tab pattern everywhere, font/color refactor with drift guards

**Status:** accepted (Cursor Phase 0–1 shipping 2026-10-28)
**From → To:** Muse → Cursor (non-quant UI work; direct route, no [quant] gate)
**Date filed:** 2026-10-28
**Depends on:** A304 (done 2026-10-28: `sub-tabs` + HeaderStats landed, CI typecheck green again). Build on that module; do not create a second one.

## Problem (Jamie's words, condensed)

- The Live tab's sub-tabs and sub-sub-tabs look clean and are easy to navigate. Other tabs do not follow the same design.
- When Jamie wants a design change, he cannot tell whether tabs share code — so refactors take a long time.
- Fonts are scattered all over fildi; the app is inconsistent everywhere and poorly styled.
- He hates light gray text. If anything it should be white — but not all white, because then significance is unreadable. The most significant data should carry color, bold, underline, or italic as appropriate.
- A previous consistency attempt decayed: new code development reintroduced inconsistencies. The plan must fix the decay mechanism, not just the current drift.

- Top-level pages (tab surfaces): home, live, macro, portfolio, rankings, watchlist, options-scanner, technical, sentiment, track-record, agents, feed, profile, settings, scorecard-explanation (plus login, not-found).
- Existing theme floor: `--muted-foreground: 215 18% 82%` — roughly at the zinc-300 floor, so the gray problem lives in per-component classes, not the theme. The Phase 0 audit counts them; do not guess the count.
- Constraints carried in: 150-line cap on new components (split shared components if they approach it); no data-logic changes in a presentation refactor; md-only pushes by Muse, code via Cursor (this row is Cursor's build).

## 1st-level analysis: what the build does

1. **Audit (Phase 0).** Inventory every tab bar, sub-tab bar, font-family declaration, and gray/muted text class across `src/`. Output is a shared-vs-bespoke map (which pages use `ui/tabs.tsx`, which use `sub-tabs` classes, which roll their own) plus counts of banned patterns. This map is the deliverable that answers "do they use the same code?" — publish it in this row's build notes.
2. **Tokens + shared components (Phase 1).** One token file owns fonts, sizes, weights, and semantic colors. One shared `<TabBar>` / `<SubTabBar>` / `<TabShell>` set (built on the existing `sub-tabs` module + `AppPage`) replaces all bespoke tab bars. Migrate Live first as the proof, Jamie eyes it, then migrate the rest.
3. **Font migration (Phase 2).** Load the approved families self-hosted (woff2, no render-blocking CDN `@import`) and map every surface to a role (table below). Remove all ad-hoc font declarations.
4. **Color/significance migration (Phase 3).** Replace every sub-floor gray with the token scale; apply the significance rules below.
5. **Drift guards (Phase 4).** A CI style-guard script + a design section in the repo's agent instructions, so a future build cannot silently reintroduce a bespoke tab bar, a gray class, or a rogue font.
6. **Visual verification (Phase 5).** Before/after screenshots for every tab; values (prices, verdicts, strikes) verified identical — styles change, data does not.

## 2nd-level analysis: why it decayed, and what stops the next decay

- Decay cause: there was no single source of truth and no enforcement. Each new tab copied whatever the nearest tab did, and the two tab systems gave every author a plausible choice. A restyle that only touches current code re-decays on the next feature.
- Guard design (three layers, all required): (a) tokens file as the only place fonts/colors are defined; (b) CI style-guard that fails on banned patterns (list in Pass/Fail) — a guard that is installed but never tested against a deliberate violation does not count; (c) agent-instruction rule (AGENTS.md/CURSOR.md design section) stating new tabs MUST use `<TabShell>` + tokens and MUST NOT invent tab bars, fonts, or gray classes. Any one layer alone rots; the three together make drift visible at build time.
- Risks: (a) font loading — self-host woff2 with `font-display: swap`; measure that first paint does not regress; (b) serifs at small sizes misread — hence the ≥20px floor for Instrument Serif and the ban on serif data; (c) script misuse — Pinyon Script is decorative only, with a size floor, so it can never creep into data; (d) color-only signaling fails accessibility — hence the pair-with-symbol rule; (e) a too-aggressive gray ban could flatten real hierarchy — the floor is zinc-300, not pure white everywhere, and hierarchy comes from size/weight/spacing too.

## Font roles (Muse's judgment on Jamie's photos)

Jamie sent five references: Instrument Serif, Pinyon Script, IvyPresto Display, Public Sans, Playfair Display. Judgment: ship three families plus the retained mono. Do NOT ship five — five fonts is how fildi got here.

| Role | Font | License / source | Used for | Never for |
|---|---|---|---|---|
| UI + body + data labels + tables | Public Sans | OFL (USWDS open source) | Nav, tabs, sub-tabs, buttons, labels, table text, tickers | — (this is the workhorse) |
| Numeric columns | Space Mono (retained, narrowed) | Already in app | Prices, strikes, premiums, P&L where monospace alignment aids scanning | Prose, labels, titles |
| Display only | Instrument Serif | OFL (Google Fonts) | Page titles, section headers, empty-state headlines (≥20px) | Tables, tickers, prices, body |
| Decorative only | Pinyon Script | OFL (Google Fonts) | Brand/wordmark accents, empty-state flourishes (≥24px) | Data, body, anything below 24px |
| Fallback only | Playfair Display | OFL | Only if Instrument Serif fails the header-readability check; do not ship both serifs | — |
| Reference only, DO NOT bundle | IvyPresto | Adobe commercial license | Style reference for high-contrast display serif | Any shipped use without a license |

Why these calls: Public Sans is the only photo that is a true data UI font (weights 100–900, built for dense interfaces) — it replaces Inter as the workhorse. Instrument Serif is the distinctive display voice from photo 1 and pairs with Public Sans. Pinyon Script is beautiful and unreadable at data sizes, so it gets the smallest, most fenced role. IvyPresto is Adobe-licensed, not freely self-hostable — verify the license before any use; the plan assumes no license and uses Instrument Serif for that job.

## Color / significance rules

- Base text is white. Secondary text floor is zinc-300 equivalent — nothing dimmer on dark surfaces. Kill list: `text-zinc-400`, `text-zinc-500`, `text-gray-400`, `text-gray-500`, arbitrary gray hexes in components, and any new muted token below the floor.
- Hierarchy without gray-out: secondary matter is differentiated by smaller size, lighter weight, or tighter spacing — never by washing it out.
- Significance (most significant data first):
  - **Color:** gain/positive green, loss/negative red, warning/attention amber, info/link blue-cyan, verdict color + bold. Color is never the only signal: pair it with ▲/▼, +/−, or a word label.
  - **Bold:** primary values, verdicts, key figures.
  - **Underline:** interactive links/actions ONLY. Never underline for emphasis.
  - **Italic:** notes, caveats, qualitative commentary ONLY (e.g. "model suggests", footnotes). Never italicize numbers, tickers, or prices.
- Semantic tokens only: components reference `text-gain`, `text-loss`, `text-warn`, `text-info`-style tokens, never raw green/red/amber hexes.

## Use cases (why this earns the build)

1. **Change the tab bar once.** Jamie wants a tab-bar tweak today and cannot tell which tabs share code. After: one shared component; the change lands everywhere from one file. Expected value: a design change goes from "audit N pages, touch N files, hope nothing was missed" to one file + guard confirmation. Check: grep shows zero bespoke tab-bar implementations outside the shared module.
2. **Read the book at a glance.** Portfolio / Rankings / Live today bury the number that matters in flat white or washed-out gray. After: P&L, verdict, and risk flags pop by color + bold; secondary context stays readable at the zinc-300 floor. Expected value: Jamie finds the significant datum without hunting, on every tab, not just Live. Check: Jamie's eyes on before/after screenshots for Portfolio + Rankings.
3. **A new tab cannot drift.** The failure mode Jamie named — new development reintroducing inconsistency. After: a future tab imports `<TabShell>` + tokens; if it invents its own tab bar, gray class, or font, the CI style-guard fails the build. Expected value: consistency survives the next ten features, not just this refactor. Check: guard demonstrably fails on a deliberately introduced violation (Pass/Fail P7).

## Downstream impact

- Touched: every page listed above; `index.css` theme; `ui/tabs.tsx`; `lib/sub-tabs.ts`; `AppPage`; every component using font, muted, zinc, or gray classes.
- NOT touched: routes, API calls, data logic, scores, verdicts, rankings math, portfolio math. Pure presentation refactor — if a number changes, the build is wrong.
- Visual: every tab looks different after (that is the point); values must not.
- Consumers of the guard: every future Cursor/Claude build in this repo (via CI + agent instructions).

## Upstream dependencies + maintenance

- Fonts: self-hosted woff2 for Public Sans, Instrument Serif, Pinyon Script (+ retained Space Mono). Verify OFL status at build time for each shipped family; IvyPresto stays out unless a license is produced.
- Guard script lives in the repo (not in an agent's head) and runs in CI; its banned-pattern list is updated only by editing the script, in review.
- Agent instructions: AGENTS.md/CURSOR.md gain a short design section (TabShell + tokens mandatory; banned patterns listed). This is a deliverable, not a suggestion.
- Ongoing: contrast audit (≥4.5:1 body) re-runs whenever the theme changes; font additions require a row, not a drive-by import.

## Pass / fail bars

- **P1 — One tab system:** every top-level page renders tabs through the shared components. Grep: zero bespoke tab-bar implementations outside the shared module.
- **P2 — No rogue type/color:** zero banned classes in `src/` (zinc-400/500, gray-400/500, arbitrary gray hexes, raw green/red/amber hexes); zero `font-family` declarations outside the token file.
- **P3 — Approved families only:** exactly Public Sans, Instrument Serif, Pinyon Script, and Space Mono (numeric-only) load, plus system fallbacks. No CDN `@import` render-blocking font load.
- **P4 — No washed-out text:** no text below the zinc-300 floor on dark surfaces; body contrast ≥4.5:1 by computed-style spot check.
- **P5 — Significance rules hold:** spot-check 10 screens: bold = primary/verdict, underline = links only, italic = notes only, color always paired with symbol/word.
- **P6 — No behavior change:** `pnpm typecheck` green + existing component tests pass; before/after value comparison (prices, verdicts, strikes) identical on every tab.
- **P7 — Guard proven, not just installed:** CI style-guard demonstrably fails on a deliberately introduced violation (bespoke tab bar or banned class), then passes once removed.
- **P8 — Decay mechanism fixed:** agent-instruction design section landed in AGENTS.md/CURSOR.md; guard script in repo + CI; Phase 0 shared-vs-bespoke map published in this row's build notes.
- **P9 — Jamie's eyes:** before/after screenshots for every tab; Live migrated first and approved by Jamie before the remaining tabs roll out.
