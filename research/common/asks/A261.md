**Build (one new module `scripts/watchlist_sync/openjev_shortlist.py`, reuse the `openjev_news` question style + `oj.post`):**
1. Per email: one OpenJev question "is this email about specific listed companies / markets, or off-topic?" → keep P(relevant) ≥ 0.5. Write the score back (`desk_commentaries.meta->openjev_relevant`) so the Haiku Daily News can skip off-topic mail (wire the skip where the Daily News selects emails; display unchanged otherwise).
2. Per kept (email or headline) × ticker in universe (tickers_mentioned or headline ticker): ask rel (about this company?), dir (good/neutral/bad), cat (earnings / guidance / analyst / M&A / product / legal / macro / other), material (big enough to move the stock?).
3. Score per ticker = Σ rel × material over items (cap 3 items/source); top 15 tickers + up to 3 peers each (same peer group, in universe, not already listed) → table `watchlist_sync.openjev_shortlist(made_on, ticker, role 'news'|'peer', of_ticker, score, dir, cats jsonb, items jsonb [{source, id, title}])`, PK (made_on, ticker).
4. Run inside `openjev_local.tick` in place of the forecast `freeze/answer` batch (keep that code, disable via a flag `FORECAST_BATCH=False` + comment citing A251), BEFORE the desk-headline labels, all on ONE model load (the Server context). After 10-24 change: the batch-started server unloads on exit — make sure the shortlist + headline labels share that one load, and later ticks with nothing new do NOT load the model.
5. Consumers (display/priority only — no scoring or selection change): `build_plan.py` adds a reasons line "news shortlist: <cat> <dir> (<n> items)" for listed names; `funnel.py --ticker` shows the flag; API field on the Model List items + a small "news" chip in `model-list-panel.tsx` (tooltip = item titles). Daily morning summary for agents: `out/shortlist/<date>.md` (≤ 30 lines: ticker, peers, why).
