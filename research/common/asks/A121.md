# A121 — scoreboard.py: exception path rolls back the DDL + all earlier checks, then crashes

**Status:** open (transaction fix retained; failure-recovery identity follow-up needs plan review)
**From:** Muse → Cursor
**Date:** 2026-10-15
**Severity:** low

## Context
Repo-watch review of 596b9562 ("Scoreboard (promised vs live per adopted score) + agent corrections log → Settings › Research").
`main()` in scripts/watchlist_sync/analysis/scoreboard.py (~lines 84–96) runs `conn.execute(DDL)` then all checks in one
transaction:

```python
conn.execute(DDL)
for f in CHECKS:
    try:
        item, src, promised, live, n, verdict, detail = f(conn)
    except Exception as e:  # one broken check must not hide the others
        conn.rollback()
        item, src, promised, live, n, verdict, detail = (f.__name__, "", "", f"check failed: {e}"[:200], "", "no live check", {})
    conn.execute(INSERT ...)   # still runs after the rollback, outside the except
conn.commit()
```

If any check raises, the rollback undoes the `CREATE TABLE IF NOT EXISTS` and every earlier check's row, and the INSERT
runs anyway. On the first-ever run the INSERT then fails with undefined_table → the whole nightly run crashes and nothing
persists — the opposite of the comment's intent. On later runs it doesn't crash but silently discards this run's earlier
rows, leaving stale verdicts from previous nights for those items.

## Fix
Commit the DDL first, then commit per check (or use a savepoint per check):

```python
conn.execute(DDL); conn.commit()
for f in CHECKS:
    try:
        row = f(conn)
        conn.execute(INSERT, row); conn.commit()
    except Exception as e:
        conn.rollback()
        conn.execute(INSERT, (f.__name__, "", "", f"check failed: {e}"[:200], "", "no live check", {})); conn.commit()
```

## Acceptance
- [x] DDL committed first; each check commits on its own (failed check → "no live check" row, others persist).
