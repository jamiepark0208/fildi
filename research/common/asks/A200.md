# A200: Peer-group drift monitor — automate A148's monthly control

**From → to:** Muse → Cursor · **Date:** 2026-10-19 · **Status:** open
**Note:** Renumbered from A181 on 2026-10-20 due to ID collision (Cursor 8e3cc1d8). Cursor's chart-history row keeps A181. A166's 2026-10-19 review cites A181 for this monthly peer control.
**Severity:** medium-high (silent input rot upstream of every score)

## Thesis

Peer-relative scoring feeds the fund score, fair value, and the Own/Avoid lists —
and peer assignments rot silently. The Oct 18 OpenJev audit proved it: 25 bad
assignments found by hand (A148), plus A160's GICS cross-check and override cleanup.
A148 left the "monthly control" open, and a manual control will lapse. The fix is a
scheduled detect-only job that replays the audit's logic monthly and flags drift to
Portfolio Alerts. Humans still approve every move — exactly as Jamie did the 25.

## Why now

- The ground truth is fresh: 25 Jamie-approved moves (c3362422/d27ace7f/fbb9ee4a)
  give a labeled set to validate the detector against. That labeled set decays in
  value every month it's unused.
- A160 already ships the machinery (WRDS sync script + majority-group SQL flags,
  GICS cross-check) — this is assembly, not research.
- A63's lesson: silent data-quality rot is the failure mode Jamie fears most
  ("market data quality is non-negotiable"); peers are the same class of rot one
  level up.

## What changes (plan-level, no code)

1. **Detector:** monthly scheduled job (research-ops threshold, not a new channel):
   for each tracked ticker, compare current peer assignment vs (a) GICS majority
   (A160's existing flags), (b) 90-day price co-move vs assigned peers (cheap,
   `prices_historical` already there). Flag assignments that fail both.
2. **Surface:** one deduped Portfolio Alerts bullet per flagged ticker
   ("X assigned to <group> but GICS says <group>, 90d corr 0.31 vs group median
   0.62") — same pattern as A174's Avoid-list flags. Jamie approves or dismisses;
   approvals write `peer_group_overrides` (the A148 mechanism).
3. **Guardrails:** detect-only — zero auto-moves, ever. Overrides survive reseeds
   (the 10-18 seed-revert bug, fixed by b2dcec36, is the cautionary tale).
4. **Calibration:** tune thresholds on the Oct 18 labeled set before scheduling.

## Use cases

- UC1: A ticker's GICS sub-industry changes after a business-model pivot — the job
  flags it next month instead of waiting for the next manual audit.
- UC2: A bad Yahoo-driven assignment (the A147 duals class) reappears after a
  reseed — flagged before it poisons fund scores.

## Acceptance

- [ ] Dry run on current assignments reproduces ≥ 80% of the 25 Oct-18 moves as
      flags, with ≤ 20% false-flag rate vs Jamie's approved list.
- [ ] Monthly schedule live; one Alerts bullet format, deduped, no new channel.
- [ ] Approving a flag writes `peer_group_overrides`; overrides survive reseeds
      (regression test on the b2dcec36 path).
- [ ] Pass: first scheduled run fires on time, flags match the dry run.
      Fail: flags fire on > 30% of assignments (threshold too loose → retune, don't ship).

## Expected results

Quantitative: recall ≥ 0.8 / false-flag ≤ 0.2 on the Oct 18 labeled set. Fewer
stale peer inputs → cleaner Own−Avoid separation over subsequent quarters.
Qualitative: the A148 monthly control becomes a job, not a memory.

## Risks

- Noisy flags erode trust — mitigated by calibrating on the labeled set and by
  detect-only design (worst case is an ignored bullet, not a bad move).
- 90d co-move is regime-sensitive (crisis correlations → 1) — GICS majority is the
  primary signal, co-move the corroborator, never the decider.
- Overlaps A166's feature-synthesis maintenance — the detector consumes it, doesn't
  duplicate it.
