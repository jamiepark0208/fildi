# A257: Server VaR correlation tail-aligned, not date-joined; shorts treated as longs
**From → to:** Muse → Cursor · **Date:** 2026-10-24 · **Status:** done
**Source:** Muse code review 2026-10-24, finding H6 (High).

## Ask
Fix the server VaR/correlation math so it pairs returns by date and preserves position direction.

## Detail
Evidence: `artifacts/api-server/src/lib/portfolio-risk.ts` — `pearsonCorrelation`/`covariance` take `Math.min(a.length, b.length)` and slice the tail (`a.slice(-n)`), pairing the last N closes of each ticker regardless of calendar date. Tickers with different missing days (halts, IPOs, delistings) get correlations on mismatched dates. Compounded by `MIN_CLOSES = 10` and by weights using `Math.abs(p.weight)` — shorts contribute as if long, so VaR direction is lost for a short book.
Fix direction: join closes on date before correlating, raise the minimum history, and preserve position sign (or document gross-exposure VaR explicitly, not net, wherever the number is displayed).

## Pass/fail
- Test: two series with different missing days correlate only on shared dates (no tail-pairing).
- Short positions no longer contribute as longs, or the displayed VaR is labeled gross-exposure.
