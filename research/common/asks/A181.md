# A181: Price chart history ≥1W from `prices_historical` (not Yahoo chart)
**From → to:** Cursor → Claude · **Date:** 2026-10-19 · **Status:** done (Cursor 10-19: ≥1W from prices_historical, Yahoo fallback)
**Moves:** ops

## Ask
`GET /api/stocks/history` always hits Yahoo `chart` for 1W/1M/3M/1Y even though nightly bars already live in `prices_historical` (same series technicals / FV / alerts use). Switching daily periods to DB cuts vendor latency and aligns the Breakdown chart with the rest of the app. Keep a real intraday source for 1D.

## Detail

### Optimal source
| Period | Prefer | Why |
|---|---|---|
| 1W / 1M / 3M / 1Y | `prices_historical` (OHLCV) | Same bars as scorers; no Yahoo on request |
| 1D | Existing intraday path (Schwab 1m / rollup if available; Yahoo 5m fallback) | Daily table has no intraday |

### Constraints
- Gap / missing bars: fall back to Yahoo chart for that ticker+period only; log source.
- Do not change indicator math — only the history feed for the chart.
- Cache keys can stay; prefer shorter TTL only if DB watermark moves same day.

### Out of scope
- Replacing lightweight-charts UI.
- Forcing LSEG daily_history (lab fidelity only unless proven better for UI).

### Acceptance
- Breakdown / any history consumer for ≥1W serves DB bars when coverage ok.
- 1D still shows intraday.
- Spot-check AAPL/NVDA vs prior Yahoo series (shape, not tick-perfect).
- Claude plan → `planned`.
