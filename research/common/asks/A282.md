## Thesis
3931405c moved SuperTrend-by-divergence to the author's pivot 2 (`dv`) while keeping the Luxy confidence engine's RSI-divergence output on pivot 5 (`dv5`, `rsi_div`). But `recent_div` — the 7th engine inside `ut_conf` — was half-edited: it takes `dv5` values at positions where `dv` is nonzero. A pivot-2 divergence confirms 3 bars before the same event's pivot-5 confirmation, so `dv5` at a `dv` firing bar is ~always 0. The divergence engine therefore votes False almost whenever it should vote True, understating `ut_conf` by ~1/7 (~14 points) on exactly the bars where a divergence fired recently.

## Evidence (read 2026-10-26, branch cursor/mac-dev, HEAD 528f0f52)
- `scripts/watchlist_sync/indicators.py`, `compute()`: `dv5 = divergences(c, r)` (default `PIV`, Luxy pivot 5) and `dv = divergences(c, r, piv=2)` (author default).
- Same function: `recent_div = np.array([dv5[max(0, i - 10):i + 1][np.nonzero(dv[max(0, i - 10):i + 1])][-1:].sum() for i in range(N)])` — outer array `dv5`, mask from `dv`. Before 3931405c both were `dv`.
- Consumer, same function: `eng` row 7 is `(recent_div == ut)`, and `out["ut_conf"] = 100 * np.nanmean(eng.astype(float), 0)` over 7 engines — so a dead row costs up to 100/7 points.
- Same-commit S102 movement is consistent, verdicts unchanged: the "UT Bot: confidence ≥ 70" rows moved (e.g. up-direction n 5,773 → 5,459) while every verdict stayed `fail` — no decision changed, which is why this is low severity, not a fire.
- Not a crash and not a live-rule change: `ut_conf` feeds the scanner badge (`options-scanner-row.tsx`, A279 tech badge) and the S102 confidence filter test, not any buy/sell gate.
