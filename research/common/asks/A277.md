## Plan

### 1. One engine, one table
`strategy_engine.py` + `strategy_rules.json` become the only picker. Nightly (daily.py 'model' stage) it writes `watchlist_sync.trade_recs_daily` (as_of, strategy, ticker, rank, gates [{input, value, pass, why}], contract (strike, expiry, Δ, bid, credit), income %/wk, expected net bp/wk + worst 5 % (S088 ladder), engine version). One row per ticker × strategy, **including names that fail a gate** (with the failing gate).

### 2. Every surface reads it (Cursor)
- **Model List › Sell puts** = top-N rows that pass every gate, then the book step (sector cap, per-name cap) → shows "N of M passing; cut by: book cap / rank".
- **Rankings › Options › Sell Puts** (Watchlist + Overall) = all rows, same rank, same contract; failed-gate rows grey with the gate chip. Live mode **re-prices the chosen contract** (bid/credit/income) but never re-picks the strike.
- **Live › Best strikes** = top-N of the same rows.
- **Structures › CSP** = the same rows (already the engine).
- TS `pickBestStrike` stops picking for display; option_score stays as one display column until a study shows it adds over IV. Breakdown › Options keeps its per-strike table.
- Income floor: one value in `strategy_rules.json` (§4). Remove the browser `minWeeklyIncome` default and the duplicate floors (rules.py / params / TS REGIME_INCOME_FLOOR) as pickers; they read the rule.

### 3. Consistency check (the acceptance test — runs nightly, fails loud)
`scripts/watchlist_sync/consistency_check.py` after the model stage. For one as_of and strategy, it calls the four APIs (Model List, /api/options/rankings, Live top options, Structures) and checks:
- (a) a ticker shown on two surfaces has the same strike + expiry;
- (b) every Model List name sits in the Rankings passing set, at a rank ≤ its Model List position + the book-cut count;
- (c) Live top-N == Rankings top-N.

Any mismatch → Portfolio Alerts + `agent_start` digest line. Unit fixture: NVDA today (4 picks → 1).
