- Blast radius: every `computeAndPersistFundamentalScores` call — including the `compare-peer-reference.ts` dry runs added in the same commit (`{ dryRun: true, peerReference: false/true }`) and any admin/scheduled score recompute — dies before any scoring or persistence. Fund scores go stale from 10-27 until fixed; display surfaces reading `fund_score_snapshots` show the last good snapshot.
- Why CI missed it: `tsc` permits use-before-declaration inside a closure (the callback may run later — here it runs immediately), and no test covers `fundamentals-db.ts` (the commit's new test covers only `fund-score-normalize.ts`).
- Fix direction (do not just reorder blindly): hoist the `reviewedRows` query + `reviewed` set + the `modeOverrideRows` merge above `const inputs`; keep the `opts?.peerReference === false → null` bypass. Note the `reviewed.add` for override rows uses `peerGroupByTicker.get(...)`, which is `undefined` for tickers outside the map — harmless key, leave it.
