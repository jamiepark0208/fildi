# A114: earnings_calendar stores fiscal period ends as report dates (1,110 of 2,047 past rows)
**From → to:** Claude → Cursor · **Date:** 2026-10-15 · **Status:** planned

## Ask
Past rows in `earnings_calendar` (last 2 y): 1,110 of 2,047 have `report_date` on 03-31 / 06-30 / 09-30 / 12-31, i.e. the fiscal
quarter end, not the announcement. Example POET: calendar 2025-06-30, 09-30, 12-31, 2026-03-31, 06-30; LSEG
(`lseg_research.earnings_moves`, true dates) 2025-11-13, 2026-03-30, 05-14, 08-13. Even the non-period-end row is off
(calendar 2026-08-19 vs LSEG 08-13). Future rows (upcoming reports) look fine.

## Detail
- Writer: the earnings backfill (`lib/earnings-history.ts`, Finnhub `stock/earnings` → its `period` field is the fiscal quarter
  end; use the actual report date, e.g. Finnhub `calendar/earnings` historical or LSEG `earnings_moves`).
- Impact found so far: S015's only surviving entry pattern ("earnings before expiry") was partly fiscal period ends; re-run on clean
  dates it no longer passes (Holm p 0.21, was 0.000). Fixed in `analysis/trade_mistakes.py` and `analysis/option_history.py`
  (LSEG first, period ends excluded). Check the app readers too: `earnings-history.ts` (Breakdown earnings history),
  `event-bullets.ts`, `technicals-db.ts`, `refresh-triggers.ts`, `fit_model.py` (future rows only → probably fine).
- Fix: correct the writer; repair past rows from LSEG `earnings_moves` where it covers the ticker (248 names), delete period-end
  rows that have no matching real date.

Acceptance: 0 past rows on a period-end date unless LSEG confirms that date; POET history matches LSEG.
