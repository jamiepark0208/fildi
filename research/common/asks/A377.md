## Ask
Fix two Highs where A367's own hygiene logic defeats its stated purpose, plus four Mediums in the same batch. New `lab_outcomes` dates are silently skipped and the SEC change signal is frozen at first fetch.

## Detail
- **H1 — `lab_fund` skip gate ignores `lab_outcomes` changes.** `scripts/watchlist_sync/analysis/lab_fund_features.py` (~L48–56): `inputs_unchanged_since_run(..., input_watermark=ibes_wm)` runs before the `NOT EXISTS lab_fund` keys query; `ibes_wm` is only `MAX(statpers)` from `wrds_research.ibes_statsum`. `lab_outcomes` can gain new rows with no IBES `statpers` change, and the function returns early — directly defeating this commit's stated purpose (lab_fund new dates only). The early return also records no `fetch_runs` row, so the skip is invisible. Fix: include a `lab_outcomes` watermark in the gate; always record the skip. Pass: adding a `lab_outcomes` row with no IBES change triggers a run.
- **H2 — Submissions refetch unreachable; change signal frozen.** `scripts/watchlist_sync/dcf/financials.py` `_submissions_newest_filing` (~L116–130): `if cached: sub = cached … elif fetch: sub = _get(…)` — `fetch=True` is passed by `companyfacts` but the fetch branch is unreachable whenever any cached submissions row exists. `prior == newest` (both from the same stale cache) on every later call; a new filing never triggers a refetch. Fix: fetch when `fetch=True` regardless of cache; compare fresh vs cached. Pass: a new filing after the first fetch triggers a refetch and a changed signal.
- **M1 — Monthly cadence diverges between the TS and Python "mirrors".** `fetch-guard.ts` (~L19–30) vs `fetch_guard.py` (~L38–53): TS `expectedSessionYmd("monthly")` walks back ≤7d to the last trading day (Sat 2026-11-07 → 2026-11-06). Python `expected_session("monthly")` returns the last trading day of the *prior* month (2026-11-06 → 2026-10-30). The same watermark yields a different `tailTo` (~1 week apart). One side is wrong; which is intended is not established in the diff. Fix: pick one definition, add a shared test. (Weekly is effectively identical to daily in both; outcomes agree.)
- **M2 — SQL/Drizzle type mismatch on `seconds`.** `lib/db/drizzle/0037_fetch_runs.sql` L13 `double precision` vs `lib/db/src/schema/index.ts` ~L1752 `numeric('seconds')`. Runtime-safe (`pg` casts a JS float into `numeric`) — schema drift (drizzle-kit would flag a diff), not a runtime break. All other columns/index names match. Fix: align the types.
- **M3 — `startFetchRun` throw leaves the 1m poll dead until restart.** `artifacts/api-server/src/lib/schwab-1m-poll.ts` (~L144–146): `startFetchRun` is awaited before the `try/finally` that clears `schwab1mPollRunning`. If it throws (DB down), the `finally` never runs and the flag stays `true` forever — poll dead until process restart. Fix: move the call inside the `try`, or clear the flag in a `catch`. Pass: a meter failure does not wedge the poll flag.
- **M4 — Parallel-worker state merge still racy.** `scripts/watchlist_sync/analysis/a359_bars_1m.py` (~L145–150): read-modify-write with no lock; two workers read the same disk state, each writes its own key via per-pid tmp + atomic `replace`, last writer wins and the other's key is lost. Consequence is re-fetch, not corruption. Fix: lock, or merge-on-write with retry.
