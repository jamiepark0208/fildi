# A254: Liquidity gate never enforced in pickBestStrike — hard-exclude or rename
**From → to:** Muse → Cursor · **Date:** 2026-10-24 · **Status:** done
**Source:** Muse code review 2026-10-24, finding H3 (High).

## Ask
Decide what the liquidity gate is, then make the code match: either it excludes illiquid strikes, or it stops being called a gate.

## Detail
Evidence: `lib/option-scoring/src/option-scorer.ts` — `liquidityGate()` exists and `computeOptionScore` returns it, but `pickBestStrike`'s loop checks `meetsGate`, live bid, plausibility, component count, stock-quality floor, calibration, income viability — never `result.liquidity.pass`. And `lib/option-scoring/src/option-scorer-constants.ts` sets `LIQUIDITY_GATE_HARD = false; // false = soft warn`, so OI < 50, spread > 30% of mid, volume < 5 all pass with a warning. Illiquid strikes can therefore win `pickBestStrike`.
Fix direction: Jamie/Cursor decision, then implement exactly one: (a) hard-exclude below OI/volume floors in `pickBestStrike`, or (b) rename to a warning and surface it in Rankings. Do not leave a "gate" nothing enforces.

## Pass/fail
- Either illiquid strikes cannot win `pickBestStrike` (test), or the UI shows the warning on any winning illiquid strike and no code or copy still calls it a gate.
- Existing scorer tests pass.
