# A175: [quant] Strategy Library page — pick a strategy, see its backtest curve, stats, and every trade
**From → to:** Claude → Cursor · **Date:** 2026-10-18 · **Status:** planned
**Moves:** ops (display). It hosts the strategies that move put/call pnl (A176–A178), and it shows how many ideas failed, which guards against data-snooping.

## Ask
Jamie wants a library of trading strategies (Jamie 2026-10-18): "my ui view allows me to filter by strategy, and a page loads with charts and statistics and description and data. the chart shows cumulative return if trading strategy executed over some past timeline (maybe just start with 2026). and it also shows transactions that would have triggered our strategy to take action, what stock/option/details/etc."
Cursor builds the page plus a read-only API. Claude owns the data: tables, runner and strategies (A176). The page **never computes trades itself**. It only reads.

## Detail
**Data contract** (Claude creates it in `scripts/watchlist_sync/schema.sql` as part of A176 step 1; read it, don't write it):
- `watchlist_sync.strategies`: one row per strategy version. Columns: `strategy_id` (slug), `version`, `name`, `family` (options-income · tail/long-option · stock-swing · index), `instrument` (stock · option · mixed), `status` (live · candidate · failed · retired), `summary` (one line), `rules_md`, `caveats_md`, `study_ref` (e.g. S046), `window_start`, `window_end`, `holdout_start`, `price_source` (real_quote · close · model), `updated_at`.
- `watchlist_sync.strategy_trades`: one row per simulated trade. Columns: `strategy_id`, `version`, `entry_ts`, `exit_ts`, `ticker`, `instrument`, `side` (long · short), `option_type`, `strike`, `expiry`, `dte_at_entry`, `qty`, `entry_px`, `exit_px`, `capital`, `pnl`, `ret_pct`, `trigger` (plain words: why it fired), `exit_reason`, `is_holdout`.
- `watchlist_sync.strategy_equity`: one row per strategy, version and day. Columns: `d`, `equity` (index, starts at 1.0), `spy_equity` (same base), `drawdown`, `is_holdout`.

**API** (new route file; pattern per `.claude/skills/api-design-patterns.md`; auth like `/research/scoreboard`):
- `GET /api/strategies`: list with headline stats, plus `tried` and `passed` counts. Filters: `family`, `status`, `instrument`.
- `GET /api/strategies/:id?version=&from=&to=`: meta, stats, equity series and trades. 404 for an unknown id.
- Stats live in **one helper** inside that route, computed from the equity and trade rows: total return, annualized return, Sharpe (daily), max drawdown, win rate, average win and average loss, profit factor, trade count, holdout return shown on its own, and return vs SPY.

**Placement (Jamie 10-19 asked AI tab vs better; Claude decided):** a **"Strategies" sub-tab of Track Record**, admin-only (seeds hold Jamie's real trades). Track Record already answers "did the calls make money?", while the AI tab is the agent team (Stage/Ideas/Usage/Rules/Skills).

**Page** Track Record › Strategies ( components per `.claude/skills/ui-components.md`):
1. Filter bar: family, status, instrument. A "Show failed" toggle, **on by default**. Header line "N strategies tried · M passed".
2. Strategy list (cards or table): name, status badge, one-line summary, return, Sharpe, max drawdown.
3. Detail view:
   - KPI tiles.
   - Cumulative return chart, strategy vs SPY. Holdout period shaded; dashed line or legend label "holdout (not tuned on)". Default range 2026-01-01 → today, with a range picker.
   - Drawdown strip under the chart.
   - Trade table: sortable, filter by ticker, columns follow `strategy_trades`. An option row shows the contract as e.g. "HOOD 10/24 $95P".
   - Description panel: `rules_md` and `caveats_md` rendered, plus the study link.
   - Tooltips stay short: headline value, with the method in the hover (memory: UI tooltips, concise).
4. Empty state: when no rows exist, show "No strategies backtested yet". Never fake data.
5. A small badge shows `price_source` when it is `model` or `close`: "prices: model". The reason is S021: model option prices ran about 25 % off.

**Acceptance (success check first):**
- `scripts/agent-ship-check.sh` passes (rule 8b).
- With A176 seed rows loaded: the API's last equity point equals the DB's last `equity` for each strategy. Total return = last equity − 1, within 1e-9.
- Trade count in the table = `count(*)` from `strategy_trades` for that strategy, version and range.
- Unknown id gives 404. Empty tables give the empty state, not an error.
- The phone layout works at 375 px wide.

**Order:** build after A176 step 1 lands the DDL plus at least one seeded strategy. Until then, use the empty state and a local fixture only.
