## Ask (Jamie 11-06, his words condensed)
"If a study just devises a strategy like 0.1Δ Friday puts and executes it every fixed interval, that is not what I need. Probabilities need to be **conditional**: the strategy executes **only if a condition is met** (e.g. sell puts intraday when RSI < 10 / < 15, then close same day after the reversal or when an RSI ceiling is breached). Backtesting needs regime matching, the number of **hits**, a list of regime/technical indicators we have, a **close condition**, and **take-profit / stop-loss** thresholds. Make sure all past and future backtests and studies are set up correctly and efficiently."

## Detail
### 1. Engine (extend `scripts/watchlist_sync/analysis/fast_screen.py`, one home)
- **Entry = condition set**, AND/OR over the indicator catalog (§2), each with a threshold. Entry fires on the bar the condition first becomes true (no repeat entries while a position is open, per ticker). Daily bars and **intraday 1m/5m bars** (London Strategic Edge 1m bars since 2003, `scripts/lse_client.py`; Polygon minute fallback).
- **Exits, first hit wins:** close condition (e.g. RSI > ceiling, close > SMA5), take-profit (% of credit captured for options / % move for stock), stop-loss (× credit or % move), time stop (same day / N bars / expiry). Report which exit fired.
- **Instrument:** stock, or short put at a target delta / % OTM picked from the chain **at entry**. Strike = nearest listed strike to the target delta (no rounding down). Option marks: real traded marks where we have them (LSE OPRA since 10/2025, `option_chain_history`), else BS on entry IV with a spread haircut calibrated from those real marks (state the haircut).
- **Output per strategy:** hits n (and N_eff after same-day/same-sector clustering), win rate, avg/median P&L, worst 5 %, exit-reason mix, avg hold. **Conditional vs unconditional:** same instrument entered on every day without the condition = base rate; lift = conditional − base. Comparators per PLAYBOOK (same-delta random entries, T-bill). Regime splits (SPY > SMA200, VIX tercile, sector). Walk-forward + DSR/PBO already in fast_screen stay.
- **Grid:** thresholds × exits swept (e.g. RSI < 10/15/20 × ceiling 50/60/70 × TP 50/75 % × SL 2×/3×), ranked with DSR so the sweep doesn't overfit.

### 2. Indicator catalog
One registry (`analysis/indicator_catalog.py` or the existing indicator home in FACTOR_MAP.md) listing every regime/technical input we can compute historically, its timeframes, and its source: RSI(2/5/14) · MFI · z-score 20/50 · gap % · ATR/RV20 · IV rank / IV÷RV (where history exists) · SMA50/200 position · 52w high/low distance · volume surge · SPY/QQQ trend · VIX level/term · sector RS · earnings window · Model List score. Exposed by the API so the lab can list it.

### 3. Backtest Lab page (`artifacts/stock-compare/src/components/backtest/backtest-lab-panel.tsx`, `/api/backtest/*`)
Condition builder from the catalog → hits count live as conditions change → exit builder (close condition, TP, SL, time stop) → results table (hits, win %, P&L, exit mix, lift vs base) + hit list (date, ticker, entry, exit, reason, P&L). Fixed-interval presets stay only as the "base rate" row.

### 4. Audit of past studies (`research/studies/INDEX.md`, ~190 rows)
Table `research/studies/conditional-audit.md`: study id · entry type (fixed-interval / conditional) · has close rule · TP/SL · hits reported · verdict still valid? Fixed-interval verdicts that feed picks/scores (A352 champion weekly book, S059 replay, Model List put backtests, A357) get re-run through the engine as conditional strategies; the rest get a one-line "base rate only" tag. Update PLAYBOOK § 0 + REVIEW.md so a study without entry condition + exit + hits fails review.

### 5. Factor discovery (Jamie 11-06 follow-up) — after engine phase 1
- **Threshold frontier:** for every catalog indicator, sweep the threshold (e.g. RSI < 5…30 step 2.5) → curve of hits vs success rate vs avg P&L. Don't assume monotonic (RSI < 10 can be capitulation / falling knife with *lower* success); report the knee.
- **Strategy menu per signal:** same entry → sell put at 0.10/0.15/0.25Δ, put spread, long stock, long call; DTE 0/7/30; each exit set. Pick the best trade for the bet, not just the best bet.
- **Multifactor model:** event table = every bar where any loose trigger fires (wide net, many hits), features = all catalog values at entry (incl. TradingView indicators in `.agents/context/indicators.md`), labels = success / P&L under the chosen trade. Logistic regression (coefficients + t) and gradient boosting (permutation / SHAP importance), purged walk-forward CV. Output: significant factors, interactions, and a probability per event. Thresholding the probability gives a tunable frontier — goal is more hits AND higher success than any single-indicator rule (compare against the best single-threshold point on the same curve).
- **Multiple testing:** FDR on factor p-values, DSR on the chosen rule, untouched holdout years, PBO across the sweep. Report N_eff (clustered same-day hits).
- **Feed the live model:** significant factors become entry timing for the Model List put picks (today technicals are display-only, weight 0) only after the benchmark gate.
