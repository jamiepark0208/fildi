# A274: Repair — /api/options/rankings ignores livePrices (A252 done claim fails at HEAD; A256 DB-only claim false for the same reason)
**From → to:** Muse → Cursor · **Date:** 2026-10-26 · **Status:** open
**Dupe check:** ASKS.md + asks/ searched. A252 is the original row (index: done) — this is its repair, not a duplicate: re-verification 2026-10-26 shows the fix is absent at HEAD. A269 (CI secret-scan) is unrelated. No other row implements the server-side flag.
**Moves:** ops (vendor-quote budget)

## Thesis
A252's acceptance is "Rankings board loads with zero vendor quote calls by default." At HEAD it does not. The rankings route calls the quote helper unconditionally, and the `livePrices=0` parameter the frontend already sends is silently ignored — so the Live table that A256 calls "DB-only" is not DB-only either. Every rankings load still fans out Schwab→Yahoo per ticker (the 60-second TTL cache only amortizes it, and every cache miss / first load pays it).

## Why now
- The false "done" hides real quote spend on the most-opened board, and the false "DB-only" label lets the Live table claim a property the server does not enforce.
- A275 (snapshot-age display) assumes DB-only is real; it is not until this row lands. Fix the enforcement first, then the label is honest.

## Evidence (read 2026-10-26, branch cursor/mac-dev, HEAD b74bb6a era)
- `artifacts/api-server/src/routes/options.ts:72-90`: `GET /api/options/rankings` reads only `side` (:73) and, for any non-empty row set, calls `getLivePrices(tickers)` (:80) unconditionally. No `livePrices` parameter is read anywhere in the file.
- `artifacts/stock-compare/src/hooks/use-top-options.ts:95`: the Live table fetches `/api/options/rankings?side=${side}&livePrices=0` believing it skips the fan-out — into a void. Comment at :2 repeats the DB-only claim.
- `artifacts/api-server/src/lib/live-quote.ts:30,33`: `getLivePrices` is a 60s TTL cache over a Yahoo batch fetch (:104) — a cache, not a skip.
- No commit in the last 100 on cursor/mac-dev mentions A252 code work (only repo-watch status syncs).

## What changes (plan-level, never code)
1. Inventory every caller of `GET /api/options/rankings` (Live table, scanner, Rankings page, any other hook) and record which wants live prices and which wants snapshot-only.
2. Server honors the flag: `livePrices=0` (and, per A252, the default with no flag) skips the quote helper entirely and returns snapshot rows without live prices; `livePrices=1` keeps current behavior. Keep the response shape stable (builder picks: `prices` present-but-empty vs omitted — and updates every caller for the choice made). No snapshot-row content changes.
3. Rankings page opts in explicitly with `livePrices=1` if it wants day-% — it must not silently lose a feature the default change removes.
4. Close the loop on A252: only after the acceptance checks pass, add a status note to A252 pointing here; do not pre-mark A252 done-via-A274.

## Use cases + expected results
- UC1: Live table opens → 0 vendor quote calls (today: 1 Yahoo batch per cache miss, per load otherwise cached). Measurable in server logs / code path, not by assertion alone.
- UC2: Rankings page with explicit opt-in still shows price + day-% exactly as today.

- A caller depending on `prices` being populated breaks on the empty shape — mitigated by keeping the key and updating callers.
