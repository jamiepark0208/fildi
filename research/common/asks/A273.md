- **02/07 Models 1–2, foundations — ARCH & GARCH, volatility clusters.**
  ARCH: σ²_t = ω + α₁ε²_{t−1} — conditional variance from past squared
  shocks only. GARCH: σ²_t = ω + α₁ε²_{t−1} + β₁σ²_{t−1} — adds past
  variance, giving smooth persistent forecasts "widely used for VaR."
  Quant reality: ARCH reacts only to yesterday's shock; GARCH remembers;
  persistence (α + β close to 1) is what real volatility looks like.
- **03/07 Models 3–4, asymmetry — GJR-GARCH & EGARCH, bad news hits
  harder.** GJR: σ²_t = ω + αε²_{t−1} + γε²_{t−1}I(ε_{t−1} < 0) +
  βσ²_{t−1} — negative shocks raise future vol more than equal positive
  ones. EGARCH: ln σ²_t = ω + β ln σ²_{t−1} + α(|z_{t−1}| − E|z|) +
  γz_{t−1} — log-variance, captures asymmetry (γ < 0) and guarantees
  positive variance without constraints. News impact curve: negative
  shocks steeper. Quant reality: equity vol rises more after falls than
  after equal rallies; symmetric GARCH misses this.
- **04/07 Models 5–6, flexible vs simple — APARCH & EWMA.**
  APARCH: σ^δ_t = ω + α(|ε_{t−1}| − γε_{t−1})^δ + βσ^δ_{t−1} —
  flexible power δ plus asymmetric shocks; nests GARCH (δ = 2, γ = 0);
  fitted here δ = 2.07. EWMA: σ²_t = λσ²_{t−1} + (1 − λ)ε²_{t−1} —
  more weight on recent shocks; λ = 0.94 is the RiskMetrics convention
  for daily data; no mean reversion. Half-lives: 11.2 days (0.94),
  22.8 days (0.97). Quant reality: EWMA is fast, transparent, one
  parameter — but never reverts to a long-run level; GARCH-family
  models do.
- **05/07 Model 7, multivariate — DCC-GARCH, correlations move too.**
  H_t = D_t R_t D_t; Q_t = (1 − a − b)Q̄ + a z_{t−1}z'_{t−1} + b Q_{t−1};
  R_t = diag(Q_t)^{−1/2} Q_t diag(Q_t)^{−1/2}. Combines each asset's
  GARCH vol (D_t) with a time-varying correlation matrix (R_t) for
  portfolio covariance forecasts. Fitted a = 0.04, b = 0.94. Quant
  reality: diversification shrinks when you need it most — correlations
  often rise in stress; static covariance hides this.
- **06/07 Applications — where are they used?** Market risk (VaR and

## 4. First-level analysis — what each model does for fildi

- **ARCH:** the null. Short memory, no persistence — the model every
  other model must beat to justify its complexity. Its fildi value is
  as a kill-bar, not as a forecast.
- **GARCH (incumbent, A270):** the persistent mean-reverting forecast
  and the current VRP-gap leg. In this plan it is the benchmark, not a
  build.
- **GJR:** the downside model. Puts are downside instruments — vol that
  rises more after falls than after rallies matters more for a
  put-selling book than symmetric vol does. The γ term is the question:
  does it actually improve next-day forecasts after down days?
- **EGARCH:** the unconstrained model. Log-variance removes positivity
  constraints — for high-vol names where GARCH fits hit parameter
  boundaries, EGARCH may fit where GARCH cannot.
- **APARCH:** the nesting test. δ is estimated, not assumed: if the data
  wants δ ≈ 2, APARCH collapses to GARCH and dies honestly (nesting is
  a built-in kill mechanism). If δ ≠ 2 with an OOS gain, the power
  matters.
- **EWMA:** the fast gauge. One parameter, transparent, instant — the
  real-time risk-panel vol vs GARCH's slower mean-reverting forecast.
  Its no-mean-reversion flaw is a display caveat, not a hidden bug.
- **DCC:** the portfolio model. The book's risk is multivariate —
  positions correlate, and correlations rise in stress (the post's
  point, and the exact failure mode of a static covariance). DCC is
  the dynamic leg; A272's MP cleaning is the cleaned static leg. The
  plan runs a three-way VaR shootout: static vs MP-cleaned vs DCC.

## 6. Use cases — every model gets at least one (why + pass/fail)

### ARCH — the null

- **UC1 — ARCH as the complexity kill-bar.** Why: if a fancy model
  cannot beat ARCH out of sample, it dies. Pass bar: every other
  model must beat ARCH on OOS forecast RMSE on the same data and
  windows; any model that fails is cut from the race output.

### GARCH — incumbent benchmark (A270 owns the build)

- **UC1 — GARCH as race benchmark + VaR comparator.** Why: the race
  needs its incumbent measured, not assumed. Pass bar: GARCH's OOS
  RMSE and VaR breach counts are published alongside every challenger
  on identical windows; no challenger ships without beating it.

### GJR-GARCH — downside asymmetry

- **UC1 — Down-day-conditioned forecast test.** Why: the γ term only
  earns its keep after falls. Pass bar: GJR beats GARCH on
  next-day-vol RMSE conditioned on down days (prior-day return < 0),
  across Model List names, or the γ term is dropped for those names.

### EGARCH — unconstrained log-variance

- **UC1 — Boundary-name test.** Why: GARCH fits hit positivity
  constraints on some high-vol names. Pass bar: on names where GARCH
  hits a boundary, EGARCH fits cleanly AND beats GARCH on OOS loglik;
  else EGARCH stays a fallback, not a default.

### APARCH — the nesting test

- **UC1 — Is δ ≠ 2?** Why: the power is the whole point of APARCH.
  Pass bar: fitted δ significantly ≠ 2 (confidence interval excludes
  2) WITH an OOS gain over GARCH; if δ ≈ 2 or no OOS gain, APARCH
  collapses to GARCH and is dropped — nesting as honest kill.

### EWMA — the fast gauge

- **UC1 — Real-time vol gauge (display).** Why: one parameter, instant,
  transparent — the risk panel's live vol. Pass bar: EWMA tracks
  realized vol with lag no worse than GARCH's on the same windows,
  with the no-mean-reversion caveat shown on the panel; else it stays
  a display line, not a forecast input.
- **UC2 — λ selection.** Why: 0.94 is a convention, not a fit. Pass
  bar: λ chosen per name by OOS fit (or 0.94 retained with evidence),
  not copied from RiskMetrics by default.

### DCC-GARCH — dynamic correlations

- **UC1 — Three-way VaR shootout: static vs MP-cleaned (A272) vs DCC.**
  Why: the book's risk number should use the best covariance, and
  there are now three candidates. Pass bar: DCC (or MP, or static)
  wins on OOS VaR backtest (Kupiec + breach counts) over identical
  windows; the winner becomes the risk-panel covariance, the losers
  are documented, not deleted.
- **UC2 — Correlation-regime flag.** Why: rising correlations in
  stress are the diversification failure the post names. Pass bar:
  DCC average pairwise correlation tracked nightly; a rise above its
  own 1-year 90th percentile raises a risk-panel flag (display-only).

### The race framework + decision rule (cross-model)

- **UC-R1 — Same-data, same-window horse race.** Why: the post's own
  design ("all six single-asset models, same data") is the right
  design — but on real fildi data. Pass bar: all six single-asset
  models + DCC fitted to identical panels and OOS windows, metrics
  published (forecast RMSE vs realized, VaR breaches, VRP-gap
  contribution). A race run on mismatched windows does not count.
- **UC-R2 — Executable decision rule.** Why: the cheat sheet must
  become code, verified. Pass bar: a per-name recommendation function
  (inputs: asymmetry evidence, persistence, multi-asset need, speed)
  whose recommendations match the race evidence on ≥80% of names;
  mismatches are listed with reasons, not hidden.
