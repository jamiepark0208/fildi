## Detail
1. **One producer, one table** `watchlist_sync.stock_context_daily` (ticker, as_of, metric, value, own_pct_3y, sector, sector_median, sector_pct, cluster = sector × vol tier, cluster_median, n_own, n_sector). Nightly, incremental from a watermark (only new as_of rows; history computed once). Metrics = every number Breakdown shows (valuation, growth, quality, leverage, bank ratios) + vol (atm IV, IV/RV, surface b/c, term 30/90, ex-earn IV from optlab.stock_surface_cm) + earnings move ratio + option spread %. Reuse peer-rankings.ts sector logic or replace it (one home; FACTOR_MAP.md line).
2. **API**: existing Breakdown payload gains `context[metric] = {own_pct, sector_median, sector_pct}` from the table (read only; p95 unchanged ±10 ms).
3. **UI (Breakdown)**: tooltip = one-line definition + this stock's line ("1.2 · sector median 1.8 · 30th pct in sector · 25th pct of own 3 y"). Colour = sector pct (or own pct for vol metrics), never a universal band. Sections whose text is identical for every stock: list them in the packet and either make them stock-specific or delete them.
4. **Models read the same table** (option params: A192 P, put engine thresholds) — no script recomputes a percentile.
**Acceptance:** 5 names (bank, biotech, utility, megacap tech, small cap) screenshot: tooltips and colours differ where the data differ; grep shows no numeric colour band left in Breakdown files (except data sanity); nightly incremental run ≤ 3 min; full rebuild time printed once.
