# A260: pm_alerts MC front-expiry only — multi-expiry books understate margin risk
**From → to:** Muse → Cursor · **Date:** 2026-10-24 · **Status:** planned
**Source:** Muse code review 2026-10-24, finding H9 (High).

## Ask
Extend the margin simulation past the front expiry, or label its number honestly as front-expiry only.

## Detail
Evidence: `scripts/watchlist_sync/pm_alerts.py`, `simulate()`: `expiring = [p for p in puts if p["expiry"] == near]` and the MC `run()` loop iterates only `expiring`; later-expiry puts enter only via `_scenario_loss`/`_market_down10`/`_hist_var` side calculations, not via `p_call`/`p_short`/`assign_p90`. A book across three expiries reports margin-call probability as if only the front expiry existed.
Fix direction: simulate assignment at each expiry (or report per-expiry risk alongside the front-expiry headline) and label the current number "front-expiry only" until then. Watch the compute cost: the greedy close search already re-runs the 20k-path MC per candidate per iteration (review finding M2) — do not multiply that cost blindly; rank candidates from the base run where possible.

## Pass/fail
- A multi-expiry book report shows per-expiry risk (or a correctly labeled front-expiry-only headline).
- Runtime stays within the existing 15-minute market-hours job budget.
