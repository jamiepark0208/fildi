# A82 — Prediction-markets data integration (Polymarket + Kalshi)

**Status:** open
**From:** Muse → Cursor (via Claude [quant] review)

**Severity:** medium

## Context
Jamie asked (Oct 14) for researched plan to integrate prediction-markets data into fildi. Web
research completed Oct 14–15 (Polymarket Gamma + CLOB APIs, Kalshi Trade API v2, trader use cases,
licensing, pitfalls, engineering patterns).

## Research headline
- **Both venues offer free, public, unauthenticated read APIs.** Polymarket Gamma
  (`gamma-api.polymarket.com`: `/events`, `/markets`, `/markets/{condition_id}`, outcomePrices =
  implied probabilities, volume, OI, bestBid/bestAsk/spread, resolution rules). Polymarket CLOB
  (`clob.polymarket.com`: `/book`, `/price`, `/midpoint`, `/prices-history`, batch endpoints,
  public websocket). Kalshi Trade API v2 (`external-api.kalshi.com/trade-api/v2`: `/markets`,
  `/markets/orderbooks` batch ≤100, `/markets/candlesticks`, `/markets/trades`, `/events`,
  `/historical/*`; websocket channels for ticks/orderbook).
- **Trader use cases**: Kalshi `KXFED`/`KXFEDDECISION` ladders → implied rate distributions via rung
  differencing; `KXCPIYOY` ladder → interpolated market-implied median CPI print; fixed-income desks
  use Fed cut-count, recession, CPI, tariff-ruling contracts.
- **Put-selling relevance**: (a) tail-probability gates from ladder differencing for sizing/strike
  selection; (b) prediction-implied vs options-implied tail cross-check (novel — no published study);
  (c) event-calendar enrichment of the sell-IV-into-event / harvest-crush playbook.
- **Pitfalls**: ~25% of Polymarket volume estimated wash trading (use OI/depth, never volume alone);
  UMA resolutions have been gamed; thin books on niche markets; calibrate before sizing.
- **LICENSING IS THE GATE**: Kalshi Data ToS prohibits redistribution/derivative works and use "to
  develop options / pre-trade risk management services" without written consent; CFTC Rule 11.1 limits
  members to internal business purposes. **Internal-only signal use is the safe harbor.** Anything
  customer-facing needs written authorization. Polymarket commercial terms undocumented — get written
  confirmation.

## What to build (phased)
- **Phase 1 — read-only ingest**: poll Gamma `/events` + Kalshi `/markets` for the macro contract
  set (FOMC decision, CPI YoY, recession, SPX level); store append-only `pred_prob_ts` (UTC) joined to
  options snapshots on event timestamps. TTLs: metadata hours, probabilities ~60s active / 1h derived.
  Batch endpoints to cut request count (~44× fewer). Monitor `updatedAt` freshness, OI/spread/two-sided
  gates; backfill via Polymarket `/prices-history` (15-day stitch) and Kalshi candlesticks.
- **Phase 2 — UI**: event panel showing market-implied odds next to the calendar (e.g. "Oct hike:
  40% per Kalshi"), with OI/depth quality badge. Internal display only per licensing.
- **Phase 3 — decision inputs** (gated): tail-probability gates feeding A74 sizing; prediction-vs-
  options-implied cross-check as a research view first, promoted only after calibration evidence.
  Never auto-trade on prediction data.
